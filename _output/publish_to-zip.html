1 Overview

Researchers asked for a Download button that gives them a file they can open: CSV first, Excel where a table is small enough, the technical formats further down, and the citation and licence travelling inside every download. A dataset page already offers the release Parquet and a CF netCDF, and ERDDAP refuses a whole-table CSV, so none of those is that file. This notebook makes it, for every dataset in the promoted release, generic over dataset_key like publish_to-netcdf.qmd and publish_to-edi.qmd.

One zip per format, named so it is recognisable in Downloads: calcofi_{dataset_key}_{since}_{format}.zip (calcofi_bottle_v2026.11.14_csv.zip, calcofi_swfsc_ichthyo_v2026.11.14_xlsx.zip; the calcofi_ prefix is not doubled), where since is the release in which the package’s content last changed (never merely the release being published). Each unzips to one folder of the same name holding:

file what
README.md what the dataset is, who collected it, the release and its date, every file and its rows, how the tables join, what was left out and where to get it, the Explorer for a subset, the dataset’s page, register-your-use and stay-informed
CITATION.md, CITATION.bib the provider’s citation where there is one (said plainly where there is not), always the release’s with its DOI
LICENSE.txt the legal code for a recognised licence id; the provider’s terms URL for custom; a plain “no licence has been established” and whom to ask otherwise
columns.csv every column: table, type, units, meaning, from the release’s own metadata.json
the tables .csv, one .xlsx workbook (a README sheet first), or .parquet

Which tables, cut how (calcofi4db::bundle_plan(), one rule each, tested): the record’s own tables[] plus the shared tables a download needs to be used alone, sample, cruise, taxon and measurement_type; a table with a dataset_key keeps this dataset’s rows, sample also keeps the samples the dataset’s rows sit on (a derived product’s observations sit on the bottle or CTD casts) and their parents, a shared vocabulary keeps the rows reached through its key, and the full-resolution supplementals (obs_ctd_full, obs_mets_full: hundreds of millions of rows partitioned by cruise) are left out and named in the README. obs is read through the catalog’s own view over obs_bio and obs_env.

A row reads without a join (calcofi4db::bundle_build_tables()): beside sample_key the station the provider recorded (site_key) and its CalCOFI line and station, which a field scientist asked for; beside taxon_key the scientific_name and common_name; beside measurement_type its units. Geometry and H3 cell-id columns are left out (latitude and longitude stay; a 64-bit cell id does not survive a spreadsheet).

Excel only where it fits (calcofi4db::bundle_format_decision()): a workbook is made when every table fits an Excel sheet: at most 1,048,575 rows of data below the header row (BUNDLE_XLSX_MAX_ROWS, Excel’s own 1,048,576-row limit; no lower cap, by the owner’s decision of 2026-11-16); otherwise the manifest says why in plain words, and a CSV too long for a spreadsheet says so in its README.

Content-addressed, the release tables’ scheme (R/release.R in calcofi4db: one object per distinct content, content_hash its identity, since the release that first carried it, upload or exists, nothing deleted). Every release re-renders every publisher; for each dataset the identity is decided before anything is written: publish_fingerprint()’s content_hash over the row signatures of exactly the tables the package holds (the release’s own order-independent signatures, so a vocabulary row another dataset added changes nothing here), the metadata its documents carry (the dataset record minus what a release re-measures, the column and table descriptions) and the pinned CC_PUBLISH_FORMAT[["zip"]]; never the code and never the release version. A content the previous manifest already lists exists: nothing is built or uploaded and only the manifest’s checked_version moves. A new content is built at {dataset_key}/{content_hash[1:24]}/ and named for its since, so its README and citation name the release it was built from (whose DOI holds exactly these data) and say the data are identical in every later release that lists it. data_hash (the data alone) is recorded beside content_hash, so a package rebuilt for a metadata change reads as “same data, new file”. The zips are byte-reproducible (bundle_zip(): fixed member order, timestamp, mode and time zone; the workbook’s timestamp fixed too).

Upload gated, and the website’s contract. Everything is written under cc_stage_path("publish", "zip"); nothing leaves the machine unless CALCOFI_PUBLISH_ZIP=true (and never in a staging run). The upload puts each new zip at gs://calcofi-db/publish/zip/{dataset_key}/{hash24}/{file}, this release’s manifest at publish/zip/releases/{version}/manifest.json (the chain of them is the history) and the current one at gs://calcofi-db/publish/zip/manifest.json, which calcofi.io reads at build time, and which release_database.qmd passes to build_dataset_catalog(bundles = ) so the next release’s datasets.json carries a kind = "bundle" distribution per file (the newest built, as the netCDF manifests do).

3 Read the release

Every table a bundle reads is resolved through the catalog (calcofi4r::cc_release_sources(), never a hand-built path) and its objects copied once into a content-addressed cache under the stage root, so twenty datasets do not read the same sample object over HTTPS twenty times, and an object unchanged since the previous release is never fetched again. obs is the catalog’s own view over obs_bio and obs_env (calcofi4r::cc_view_sql()).

# the previous manifest: this machine's last run, else what the bucket serves (a staging run
# never reads the bucket's). A schema-1.0 entry has no content_hash, so every dataset it lists
# is new content to this scheme once.
read_prior <- function() {
  p <- file.path(OUT_DIR, "manifest.json")
  m <- if (file.exists(p)) tryCatch(read_j(p), error = function(e) NULL) else if (!STAGING) fetch_bundle_manifest()
  setNames(m$datasets %||% list(), vapply(m$datasets %||% list(), `[[`, "", "dataset_key"))
}
prior_all  <- read_prior()
code_parts <- publish_code_parts(CODE_FILES)
cols_meta  <- meta$columns %||% list()
tbls_meta  <- meta$tables %||% list()
entries <- list(); runs <- list()

for (k in keys) {
  t0   <- Sys.time()
  rec  <- records[[k]]
  plan <- plans[[k]]
  built <- bundle_build_tables(con, plan, k, from_sql)
  # the identity, decided BEFORE anything is written: the bundle's own rows (the release's
  # row signatures), the metadata its documents carry and the pinned format, never the code
  # or the release version (calcofi4db::publish_fingerprint(), the release tables' scheme)
  fp <- publish_fingerprint(
    data     = bundle_table_signatures(con, built$table),
    metadata = list(
      record  = publish_record_digest(rec),   # minus what a release re-measures
      columns = cols_meta[sub("\\..*$", "", names(cols_meta)) %in% built$table],
      tables  = tbls_meta[intersect(built$table, names(tbls_meta))],
      plan    = plan[, c("table", "included", "rule", "link", "reason")],
      built   = built[, c("table", "dropped", "added")]),
    code     = code_parts,
    format   = CC_PUBLISH_FORMAT[["zip"]])
  prior <- prior_all[[k]]
  same  <- identical(prior$content_hash %||% "", fp$content_hash)
  if (same) {
    # exists: the object (and its since) is the previous one; only the manifest's release moves
    e <- prior
    e$checked_version <- RELEASE_VERSION
    action <- "exists"
    cat(glue("- `{k}`: content {substr(fp$content_hash, 1, 12)} unchanged since {e$since %||% e$version} — ",
             "nothing written"), "\n")
  } else {
    obj_dir <- file.path(STAGE_DIR, k, substr(fp$content_hash, 1, 24))   # publish/zip/{key}/{hash24}/
    w <- write_bundle(con, rec, release, built, plan, obj_dir,
                      meta_columns = cols_meta, meta_tables = tbls_meta, licenses_dir = LIC_DIR)
    lic <- bundle_license(rec, LIC_DIR); cit <- bundle_citation(rec, release)
    e <- bundle_manifest_entry(rec, RELEASE_VERSION, release$release_date, RELEASE_VERSION, fp, built, plan, w,
                               license_kind = lic$kind, has_provider_citation = cit$has_provider_citation)
    action <- "upload"
    why <- if (is.null(prior)) "no previous package" else if (is.null(prior$content_hash))
      "first content-addressed build" else if (identical(prior$data_hash %||% "", fp$data_hash))
      "same data, its metadata or format changed" else "the data changed"
    cat(glue("- `{k}`: new content {substr(fp$content_hash, 1, 12)} ({why}); ",
             "{paste(sprintf('%s %s MB', w$format[w$written], format(round(w$bytes[w$written] / 1e6, 1), nsmall = 1)), collapse = ', ')}"), "\n")
  }
  for (tb in built$table) dbExecute(con, glue('DROP TABLE IF EXISTS "bundle_{tb}"'))
  entries[[k]] <- e
  runs[[k]] <- tibble(dataset_key = k, action = action,
                      changed = if (same) "" else paste(changed_inputs(fp, list(parts = as.list(unlist(prior$input_fingerprint$parts)))), collapse = ","),
                      secs = round(as.numeric(difftime(Sys.time(), t0, units = "secs"))))
}

## Overview

Researchers asked for a **Download** button that gives them a file they can open: CSV first,
Excel where a table is small enough, the technical formats further down, and the citation and
licence travelling inside every download. A dataset page already offers the release Parquet and a
CF netCDF, and ERDDAP refuses a whole-table CSV, so none of those is that file. This notebook
makes it, for every dataset in the promoted release, generic over `dataset_key` like
`publish_to-netcdf.qmd` and `publish_to-edi.qmd`.

**One zip per format, named so it is recognisable in Downloads:**
`calcofi_{dataset_key}_{since}_{format}.zip` (`calcofi_bottle_v2026.11.14_csv.zip`,
`calcofi_swfsc_ichthyo_v2026.11.14_xlsx.zip`; the `calcofi_` prefix is not doubled), where `since`
is the release in which the package's content last changed (never merely the release being
published). Each unzips to one folder of the same name holding:

| file | what |
|---|---|
| `README.md` | what the dataset is, who collected it, the release and its date, every file and its rows, how the tables join, what was left out and where to get it, the Explorer for a subset, the dataset's page, register-your-use and stay-informed |
| `CITATION.md`, `CITATION.bib` | the provider's citation where there is one (said plainly where there is not), always the release's with its DOI |
| `LICENSE.txt` | the legal code for a recognised licence id; the provider's terms URL for `custom`; a plain "no licence has been established" and whom to ask otherwise |
| `columns.csv` | every column: table, type, units, meaning, from the release's own `metadata.json` |
| the tables | `.csv`, one `.xlsx` workbook (a README sheet first), or `.parquet` |

**Which tables, cut how** (`calcofi4db::bundle_plan()`, one rule each, tested): the record's own
`tables[]` plus the shared tables a download needs to be used alone, `sample`, `cruise`, `taxon`
and `measurement_type`; a table with a `dataset_key` keeps this dataset's rows, `sample` also
keeps the samples the dataset's rows sit on (a derived product's observations sit on the bottle or
CTD casts) and their parents, a shared vocabulary keeps the rows reached through its key, and the
full-resolution supplementals (`obs_ctd_full`, `obs_mets_full`: hundreds of millions of rows
partitioned by cruise) are left out and named in the README. `obs` is read through the catalog's
own view over `obs_bio` and `obs_env`.

**A row reads without a join** (`calcofi4db::bundle_build_tables()`): beside `sample_key` the
station the provider recorded (`site_key`) and its CalCOFI `line` and `station`, which a field
scientist asked for; beside `taxon_key` the `scientific_name` and `common_name`; beside
`measurement_type` its `units`. Geometry and H3 cell-id columns are left out (`latitude` and
`longitude` stay; a 64-bit cell id does not survive a spreadsheet).

**Excel only where it fits** (`calcofi4db::bundle_format_decision()`): a workbook is made when
every table fits an Excel sheet: at most 1,048,575 rows of data below the header row
(`BUNDLE_XLSX_MAX_ROWS`, Excel's own 1,048,576-row limit; no lower cap, by the owner's decision of
2026-11-16); otherwise the manifest says why in plain words, and a CSV too long for a
spreadsheet says so in its README.

**Content-addressed, the release tables' scheme** (`R/release.R` in calcofi4db: one object per
distinct content, `content_hash` its identity, `since` the release that first carried it,
`upload` or `exists`, nothing deleted). Every release re-renders every publisher; for each
dataset the identity is decided **before anything is written**: `publish_fingerprint()`'s
`content_hash` over the row signatures of exactly the tables the package holds (the release's
own order-independent signatures, so a vocabulary row another dataset added changes nothing
here), the metadata its documents carry (the dataset record minus what a release re-measures,
the column and table descriptions) and the pinned `CC_PUBLISH_FORMAT[["zip"]]`; never the code
and never the release version. A content the previous manifest already lists **exists**: nothing
is built or uploaded and only the manifest's `checked_version` moves. A new content is built at
`{dataset_key}/{content_hash[1:24]}/` and named for its `since`, so its README and citation name
the release it was built from (whose DOI holds exactly these data) and say the data are
identical in every later release that lists it. `data_hash` (the data alone) is recorded beside
`content_hash`, so a package rebuilt for a metadata change reads as "same data, new file". The
zips are byte-reproducible (`bundle_zip()`: fixed member order, timestamp, mode and time zone;
the workbook's timestamp fixed too).

**Upload gated, and the website's contract.** Everything is written under
`cc_stage_path("publish", "zip")`; nothing leaves the machine unless `CALCOFI_PUBLISH_ZIP=true`
(and never in a staging run). The upload puts each new zip at
`gs://calcofi-db/publish/zip/{dataset_key}/{hash24}/{file}`, this release's manifest at
`publish/zip/releases/{version}/manifest.json` (the chain of them is the history) and the current
one at
`gs://calcofi-db/publish/zip/manifest.json`, which calcofi.io reads at build time, and which
`release_database.qmd` passes to `build_dataset_catalog(bundles = )` so the next release's
`datasets.json` carries a `kind = "bundle"` distribution per file (the newest built, as the
netCDF manifests do).

## Read the release

Every table a bundle reads is resolved through the catalog (`calcofi4r::cc_release_sources()`,
never a hand-built path) and its objects copied once into a content-addressed cache under the
stage root, so twenty datasets do not read the same `sample` object over HTTPS twenty times, and
an object unchanged since the previous release is never fetched again. `obs` is the catalog's own
view over `obs_bio` and `obs_env` (`calcofi4r::cc_view_sql()`).

read_prior <- function() {
  p <- file.path(OUT_DIR, "manifest.json")
  m <- if (file.exists(p)) tryCatch(read_j(p), error = function(e) NULL) else if (!STAGING) fetch_bundle_manifest()
  setNames(m$datasets %||% list(), vapply(m$datasets %||% list(), `[[`, "", "dataset_key"))
}
prior_all  <- read_prior()
code_parts <- publish_code_parts(CODE_FILES)
cols_meta  <- meta$columns %||% list()

entries <- list(); runs <- list()

for (k in keys) {
  t0   <- Sys.time()
  rec  <- records[[k]]
  plan <- plans[[k]]
  built <- bundle_build_tables(con, plan, k, from_sql)
  # the identity, decided BEFORE anything is written: the bundle's own rows (the release's
  # row signatures), the metadata its documents carry and the pinned format, never the code
  # or the release version (calcofi4db::publish_fingerprint(), the release tables' scheme)
  fp <- publish_fingerprint(
    data     = bundle_table_signatures(con, built$table),
    metadata = list(
      record  = publish_record_digest(rec),   # minus what a release re-measures
      columns = cols_meta[sub("\\..*$", "", names(cols_meta)) %in% built$table],
      tables  = tbls_meta[intersect(built$table, names(tbls_meta))],
      plan    = plan[, c("table", "included", "rule", "link", "reason")],
      built   = built[, c("table", "dropped", "added")]),
    code     = code_parts,
    format   = CC_PUBLISH_FORMAT[["zip"]])
  prior <- prior_all[[k]]
  same  <- identical(prior$content_hash %||% "", fp$content_hash)
  if (same) {
    # exists: the object (and its since) is the previous one; only the manifest's release moves
    e <- prior
    e$checked_version <- RELEASE_VERSION
    action <- "exists"
    cat(glue("- `{k}`: content {substr(fp$content_hash, 1, 12)} unchanged since {e$since %||% e$version} — ",
             "nothing written"), "\n")
  } else {
    obj_dir <- file.path(STAGE_DIR, k, substr(fp$content_hash, 1, 24))   # publish/zip/{key}/{hash24}/
    w <- write_bundle(con, rec, release, built, plan, obj_dir,
                      meta_columns = cols_meta, meta_tables = tbls_meta, licenses_dir = LIC_DIR)
    lic <- bundle_license(rec, LIC_DIR); cit <- bundle_citation(rec, release)
    e <- bundle_manifest_entry(rec, RELEASE_VERSION, release$release_date, RELEASE_VERSION, fp, built, plan, w,
                               license_kind = lic$kind, has_provider_citation = cit$has_provider_citation)
    action <- "upload"
    why <- if (is.null(prior)) "no previous package" else if (is.null(prior$content_hash))
      "first content-addressed build" else if (identical(prior$data_hash %||% "", fp$data_hash))
      "same data, its metadata or format changed" else "the data changed"
    cat(glue("- `{k}`: new content {substr(fp$content_hash, 1, 12)} ({why}); ",
             "{paste(sprintf('%s %s MB', w$format[w$written], format(round(w$bytes[w$written] / 1e6, 1), nsmall = 1)), collapse = ', ')}"), "\n")
  }
  for (tb in built$table) dbExecute(con, glue('DROP TABLE IF EXISTS "bundle_{tb}"'))
  entries[[k]] <- e
  runs[[k]] <- tibble(dataset_key = k, action = action,
                      changed = if (same) "" else paste(changed_inputs(fp, list(parts = as.list(unlist(prior$input_fingerprint$parts)))), collapse = ","),
                      secs = round(as.numeric(difftime(Sys.time(), t0, units = "secs"))))

## The manifest: what the website reads

`data/zip/manifest.json` (and the same file beside the zips) is the contract with calcofi.io
(schema 1.1): one entry per dataset with its `since` (also `version`, for a 1.0 reader), the
release it was last confirmed against (`checked_version`), its `content_hash` and `data_hash`,
the licence kind, whether the provider gave a citation, every table's rows, what was left out,
and per format either the file (`url`, `bytes`, `sha256`, `excel_openable`) or, for a format not
offered, the reason in plain words. It carries no clock time, so an unchanged run rewrites it
byte for byte. `manifest.csv` is the same per dataset × format, with whether the bucket already
holds those bytes.
