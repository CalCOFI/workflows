1 Overview

Source: Bottle Database | CalCOFI.org

  • Download: https://calcofi.org/downloads/database/CalCOFI_Database_194903-202105_csv_16October2023.zip

Goal: Ingest bottle database from source CSV files into a local wrangling DuckDB, then export as parquet files for downstream use.

Two source tables:

  • 194903-202105_Cast.csv (61 fields) — station-level: cruise, location, meteorology, integrated measurements
  • 194903-202105_Bottle.csv (62 fields) — sample-level: depth, temperature, salinity, O₂, nutrients, pigments, C14, pH

Coverage: 1949-03 to 2021-05 (72 years)

Join key: cast_id (in both tables; source column Cst_Cnt)

This workflow processes CalCOFI bottle database CSV files and outputs parquet files. The workflow:

  1. Reads CSV files from source directory (with GCS archive sync)
  2. Loads into local wrangling DuckDB with column renames
  3. Applies ship name/code corrections
  4. Consolidates temporal columns into datetime_start_utc, drops derivable columns, creates casts_derived VIEW
  5. Pivots bottle measurements into long-format bottle_measurement table
  6. Pivots cast environmental conditions into cast_condition table
  7. Loads measurement_type reference table
  8. Validates primary keys and foreign key integrity
  9. Adds spatial geometry and grid assignments
  10. Exports to parquet files (for later integration into Working DuckLake)

8 Column Naming Rationale

The column renames in flds_redefine.csv follow these db conventions:

  • *_id for integer primary/foreign keys (e.g. Cst_Cnt → cast_id, Btl_Cnt → bottle_id)
  • *_key for varchar natural/composite keys (e.g. Cast_ID → cast_key, Sta_ID → site_key)
  • Note: Cruise_ID → cruise_key_0 (interim _0 suffix avoids collision with SWFSC cruise_key YYYY-MM-NODC; discarded after merge)
  • unit suffixes for measurements (e.g. Depthm → depth_m)

8.1 Ambiguous column pairs

Column pair Why different
Cst_Cnt (→ cast_id) vs Cast_ID (→ cast_key) integer counter (1, 2, 3…) vs varchar composite (19-4903CR-HY-060-0930-05400560)
Sta_ID (→ site_key) vs DbSta_ID (→ db_sta_key) “054.0 056.0” (space-separated) vs “05400560” (compact, derivable)
Depth_ID (→ depth_key) vs Depthm (→ depth_m) varchar identifier vs numeric depth in meters

8.2 R_* = “Reported” (pre-QC) values

The R_* prefix means original instrument values before quality control. Critical: R_Sal (Specific Volume Anomaly, values ~233, units 10⁻⁸ m³/kg) is a completely different parameter/scale than Salnty (Practical Salinity PSS-78, values ~33.44). These are pivoted as distinct measurement types (r_salinity_sva vs salinity).

# -- create datetime_start_utc from date + time (idempotent) ----
casts_cols <- dbListFields(con, "casts")

if ("date" %in% casts_cols && "time" %in% casts_cols) {
  # date is DATE type (e.g. 1949-03-01), time is INTERVAL (e.g. 09:30:00)
  # adding DATE + INTERVAL yields TIMESTAMP; 324 casts have NULL time
  dbExecute(con, "ALTER TABLE casts ADD COLUMN IF NOT EXISTS datetime_start_utc TIMESTAMP")
  dbExecute(
    con,
    "
    UPDATE casts SET datetime_start_utc =
      CASE
        WHEN \"time\" IS NOT NULL
        THEN CAST(\"date\" AS TIMESTAMP) + \"time\"
        ELSE CAST(\"date\" AS TIMESTAMP)
      END"
  )
  say(glue(
    "Created datetime_start_utc: {dbGetQuery(con, 'SELECT COUNT(*) FROM casts WHERE datetime_start_utc IS NOT NULL')[[1]]} non-null values"

    str_detect(`_source_datasets`, "calcofi_bottle"),

    value_col = `_source_column`,

    qual_col = `_qual_column`

  mutate(across(c(prec_col, qual_col), ~ na_if(.x, "")))

  bottle_meas_map,
  function(
    measurement_type,
    value_col,
    prec_col,
    qual_col

12 Load Measurement Type Reference

Load the measurement_type lookup table that provides units and descriptions for all measurement/condition types across datasets.

12.1 measurement_type vs lookup

The measurement_type table and the swfsc lookup table serve fundamentally different purposes:

  • measurement_type answers “what was measured?” — provides metadata (units, description, source provenance) for measurement codes used in bottle_measurement, cast_condition, and ichthyo
  • lookup answers “what does this code mean?” — translates categorical values (egg developmental stages 1-11, larva stages, tow types) into human-readable descriptions

Merging would create a sparse table with many NULL columns (e.g., units/_source_column NULL for egg stages; lookup_num/lookup_chr NULL for temperature). Both tables coexist in the Working DuckLake, loaded from their respective upstream workflows.

16.1 Primary Key Strategy

Note on UUID-first approach: The SWFSC ichthyo tables use source UUIDs (minted at sea) as primary identifiers. The bottle/cast tables are different — they use source integer counters (Cst_Cnt, Btl_Cnt) as natural keys, which are stable identifiers from the source system. The pivoted tables (bottle_measurement, cast_condition) have no source identifier and use sequential integer IDs for convenience, with composite natural keys enforced as unique.

bottle bottle_id Source integer counter (Btl_Cnt) — stable source key

  # vice versa), and a re-run inside one session finds the view already there
  t <- dbGetQuery(con, glue(
    "SELECT table_type FROM information_schema.tables WHERE table_name = '{nm}'"))

    kind <- if (grepl("VIEW", t$table_type[1], ignore.case = TRUE)) "VIEW" else "TABLE"

## Overview

**Source**: [Bottle Database | CalCOFI.org](https://calcofi.org/data/oceanographic-data/bottle-database/)

- Download: <https://calcofi.org/downloads/database/CalCOFI_Database_194903-202105_csv_16October2023.zip>

**Goal**: Ingest bottle database from source CSV files into a local
wrangling DuckDB, then export as parquet files for downstream use.

**Two source tables**:

- `194903-202105_Cast.csv` (61 fields) — station-level: cruise,
  location, meteorology, integrated measurements
- `194903-202105_Bottle.csv` (62 fields) — sample-level: depth,
  temperature, salinity, O₂, nutrients, pigments, C14, pH

**Coverage**: 1949-03 to 2021-05 (72 years)

**Join key**: `cast_id` (in both tables; source column `Cst_Cnt`)

This workflow processes CalCOFI bottle database CSV files and outputs
parquet files. The workflow:

1. Reads CSV files from source directory (with GCS archive sync)
2. Loads into local wrangling DuckDB with column renames
3. Applies ship name/code corrections
4. Consolidates temporal columns into `datetime_start_utc`, drops derivable columns, creates `casts_derived` VIEW
5. Pivots bottle measurements into long-format `bottle_measurement` table
6. Pivots cast environmental conditions into `cast_condition` table
7. Loads `measurement_type` reference table
8. Validates primary keys and foreign key integrity
9. Adds spatial geometry and grid assignments
10. Exports to parquet files (for later integration into Working DuckLake)

## Column Naming Rationale

The column renames in `flds_redefine.csv` follow these db conventions:

- **`*_id`** for integer primary/foreign keys (e.g. `Cst_Cnt` → `cast_id`, `Btl_Cnt` → `bottle_id`)
- **`*_key`** for varchar natural/composite keys (e.g. `Cast_ID` → `cast_key`, `Sta_ID` → `site_key`)
- Note: `Cruise_ID` → `cruise_key_0` (interim `_0` suffix avoids collision with SWFSC `cruise_key` YYYY-MM-NODC; discarded after merge)
- **unit suffixes** for measurements (e.g. `Depthm` → `depth_m`)

### Ambiguous column pairs

| Column pair | Why different |
|------------|---------------|
| `Cst_Cnt` (→ `cast_id`) vs `Cast_ID` (→ `cast_key`) | integer counter (1, 2, 3...) vs varchar composite (19-4903CR-HY-060-0930-05400560) |
| `Sta_ID` (→ `site_key`) vs `DbSta_ID` (→ `db_sta_key`) | "054.0 056.0" (space-separated) vs "05400560" (compact, derivable) |
| `Depth_ID` (→ `depth_key`) vs `Depthm` (→ `depth_m`) | varchar identifier vs numeric depth in meters |

### `R_*` = "Reported" (pre-QC) values

The `R_*` prefix means original instrument values before quality control.
**Critical**: `R_Sal` (Specific Volume Anomaly, values ~233, units 10⁻⁸ m³/kg)
is a **completely different parameter/scale** than `Salnty` (Practical Salinity
PSS-78, values ~33.44). These are pivoted as distinct measurement types
(`r_salinity_sva` vs `salinity`).

## Load Measurement Type Reference

Load the `measurement_type` lookup table that provides units and
descriptions for all measurement/condition types across datasets.

### `measurement_type` vs `lookup`

The `measurement_type` table and the swfsc `lookup` table serve fundamentally different purposes:

- **`measurement_type`** answers "what was measured?" — provides metadata (units, description, source provenance) for measurement codes used in `bottle_measurement`, `cast_condition`, and `ichthyo`
- **`lookup`** answers "what does this code mean?" — translates categorical values (egg developmental stages 1-11, larva stages, tow types) into human-readable descriptions

Merging would create a sparse table with many NULL columns (e.g., `units`/`_source_column` NULL for egg stages; `lookup_num`/`lookup_chr` NULL for temperature). Both tables coexist in the Working DuckLake, loaded from their respective upstream workflows.

### Primary Key Strategy

**Note on UUID-first approach**: The SWFSC ichthyo tables use source UUIDs (minted
at sea) as primary identifiers. The bottle/cast tables are different — they use
source integer counters (`Cst_Cnt`, `Btl_Cnt`) as natural keys, which are stable
identifiers from the source system. The pivoted tables (`bottle_measurement`,
`cast_condition`) have no source identifier and use sequential integer IDs for
convenience, with composite natural keys enforced as unique.

| Table | Primary Key | Type |
|-------|-------------|------|
| `casts` | `cast_id` | Source integer counter (`Cst_Cnt`) — stable source key |
| `bottle` | `bottle_id` | Source integer counter (`Btl_Cnt`) — stable source key |
| `bottle_measurement` | `bottle_measurement_id` | Sequential (derived/pivoted table); composite `(bottle_id, measurement_type)` enforced unique |
| `cast_condition` | `cast_condition_id` | Sequential (derived/pivoted table); composite `(cast_id, condition_type)` enforced unique |
| `measurement_type` | `measurement_type` | Natural key (type code string) |
| `grid` | `grid_key` | Natural key |

### Foreign Key Relationships

```
casts.cast_id (PK, integer) — station-level
    ↓
bottle.bottle_id (PK, integer) — sample-level
bottle.cast_id (FK) → casts.cast_id
    ↓
bottle_measurement.bottle_measurement_id (PK, integer) — ROW_NUMBER(ORDER BY bottle_id, measurement_type)
bottle_measurement.bottle_id (FK) → bottle.bottle_id
bottle_measurement.measurement_type (FK) → measurement_type.measurement_type

cast_condition.cast_condition_id (PK, integer) — ROW_NUMBER(ORDER BY cast_id, condition_type)
cast_condition.cast_id (FK) → casts.cast_id
cast_condition.condition_type (FK) → measurement_type.measurement_type

casts.grid_key (FK) → grid.grid_key (after spatial join)
casts.ship_code (soft FK) → ship.ship_nodc (validated after integration with swfsc)
```

## Emit Core Tables

Project this dataset into the shared consolidated core model
(`design_env-bio-consolidation.md`). These core tables **are** this ingest's
output: `release_database.qmd` concatenates the per-dataset shards rather than
re-deriving the core, so there is exactly one projection to keep correct.

Bottle is a two-level hierarchy — `cast` -> `bottle` — carried in `sample` as an
adjacency list. Cast conditions become `sample_measurement` (they describe the
event, not an observation); the long `bottle_measurement` values become `obs` at
`realm = 'env'`.

`bottom_depth` rides along in `cast_condition`: the pivot above turns the source
`Bottom_D` column into a condition row and drops it from `casts`, so the cast's
water depth reaches `sample_measurement` through the same arm as wind speed and
sea state rather than needing one of its own. An added
`UNION ALL SELECT bottom_depth_m FROM casts` would be both redundant *and* a
binder error — that column no longer exists by the time this runs.

::: {.callout-important}
## This section must run AFTER Cross-Dataset Integration

`sample` carries `cruise_key`, and `cruise_key` is only resolved on `casts` by
the ship match + `derive_cruise_key()` above. If the projection runs first,
`cruise_key` is silently NULL on all 895,371 bottles instead of 99.93% populated
— no error, just a column of NULLs in the release.
:::

```{r}
#| label: emit_core

ds_key <- "calcofi_bottle"

# This projection lives here, in the notebook that owns the dataset, not in a
# switch(dataset_key, ...) arm inside calcofi4db. Bottle is env-only: no taxa
# references, no taxon_key on obs.
#
# sample — two levels: cast (root) and bottle (leaf, parent = its cast). The
# bottle inherits the cast's position/time/grid/cruise; only depth is its own.
append_sample(con, glue("
  SELECT {ns_key(ds_key, 'cast', 'cast_id')} AS sample_key, 'cast' AS sample_type,
         NULL::VARCHAR AS parent_sample_key,
         {ns_key(ds_key, 'cast', 'cast_id')} AS root_sample_key,
         '{ds_key}' AS dataset_key, grid_key, site_key, cruise_key,
         CAST(order_occ AS INTEGER) AS order_occ,
         latitude, longitude, CAST(datetime_start_utc AS TIMESTAMP) AS datetime,
         NULL::DOUBLE AS depth_min_m, NULL::DOUBLE AS depth_max_m,
         NULL::VARCHAR AS tow_type
  FROM casts"))
append_sample(con, glue("
  SELECT {ns_key(ds_key, 'bottle', 'b.bottle_id')} AS sample_key, 'bottle' AS sample_type,
         {ns_key(ds_key, 'cast', 'b.cast_id')} AS parent_sample_key,
         {ns_key(ds_key, 'cast', 'b.cast_id')} AS root_sample_key,
         '{ds_key}' AS dataset_key, c.grid_key, b.site_key, c.cruise_key,
         CAST(c.order_occ AS INTEGER) AS order_occ, c.latitude, c.longitude,
         CAST(c.datetime_start_utc AS TIMESTAMP) AS datetime,
         b.depth_m AS depth_min_m, b.depth_m AS depth_max_m,
         NULL::VARCHAR AS tow_type
  FROM bottle b JOIN casts c USING (cast_id)"))

# obs — the long bottle measurements, at realm = 'env'
append_obs(con, glue("
  SELECT 'env', '{ds_key}', {ns_key(ds_key, 'bottle', 'b.bottle_id')},
         c.grid_key, c.cruise_key, c.latitude, c.longitude,
         CAST(c.datetime_start_utc AS TIMESTAMP), b.depth_m, b.depth_m,
         NULL::VARCHAR, NULL::VARCHAR,
         m.measurement_type, m.measurement_value, m.measurement_qual, m.measurement_prec
  FROM bottle_measurement m JOIN bottle b USING (bottle_id) JOIN casts c USING (cast_id)
  WHERE c.grid_key IS NOT NULL"))

# sample_measurement — event-level cast conditions (wind, sea state, bottom
# depth, …). `cast_id` is DOUBLE in cast_condition, so cast through BIGINT first
# or every key comes out as '…:cast:5.0' and orphans against sample.
append_sample_measurement(con, glue("
  SELECT {ns_key(ds_key, 'cast', 'CAST(cast_id AS BIGINT)')}, '{ds_key}',
         condition_type, condition_value, NULL::VARCHAR
  FROM cast_condition"))

core <- list(
  sample             = dbGetQuery(con, "SELECT COUNT(*) FROM sample")[[1]],
  obs                = dbGetQuery(con, "SELECT COUNT(*) FROM obs")[[1]],
  sample_measurement = dbGetQuery(con, "SELECT COUNT(*) FROM sample_measurement")[[1]])
cat(glue(
  "core projection — sample={core$sample %||% 0} obs={core$obs %||% 0} ",
  "sample_measurement={core$sample_measurement %||% 0}\n"))

n_cast <- dbGetQuery(con, "SELECT COUNT(*) FROM sample WHERE sample_type='cast'")[[1]]
n_btl  <- dbGetQuery(con, "SELECT COUNT(*) FROM sample WHERE sample_type='bottle'")[[1]]
n_bd   <- dbGetQuery(con, "SELECT COUNT(*) FROM sample_measurement WHERE measurement_type='bottom_depth'")[[1]]
n_ck   <- dbGetQuery(con, "SELECT COUNT(*) FROM sample WHERE sample_type='bottle' AND cruise_key IS NOT NULL")[[1]]
stopifnot(
  "sample must hold one row per cast"   = n_cast == dbGetQuery(con, "SELECT COUNT(DISTINCT cast_id) FROM casts")[[1]],
  "sample must hold one row per bottle" = n_btl  == dbGetQuery(con, "SELECT COUNT(DISTINCT bottle_id) FROM bottle")[[1]],
  "sample_key must be globally unique" =
    dbGetQuery(con, "SELECT COUNT(*) FROM (SELECT sample_key FROM sample
                     GROUP BY 1 HAVING COUNT(*) > 1)")[[1]] == 0,
  "obs must be one row per grid-matched bottle measurement" =
    core$obs ==
    dbGetQuery(con, "SELECT COUNT(*) FROM bottle_measurement m JOIN bottle b USING (bottle_id)
                     JOIN casts c USING (cast_id) WHERE c.grid_key IS NOT NULL")[[1]],
  "every bottle must resolve to its cast" =
    dbGetQuery(con, "SELECT COUNT(*) FROM sample c LEFT JOIN sample p
                     ON c.parent_sample_key = p.sample_key
                     WHERE c.parent_sample_key IS NOT NULL AND p.sample_key IS NULL")[[1]] == 0,
  "sample_measurement must be one row per cast condition, not duplicated" =
    core$sample_measurement == dbGetQuery(con, "SELECT COUNT(*) FROM cast_condition")[[1]],
  "every sample_measurement.sample_key must resolve in sample (the DOUBLE cast_id trap)" =
    dbGetQuery(con, "SELECT COUNT(*) FROM sample_measurement m
                     LEFT JOIN sample s USING (sample_key)
                     WHERE s.sample_key IS NULL")[[1]] == 0,
  "bottom_depth must reach sample_measurement" = n_bd > 0,
  # guards the chunk-order constraint above: cruise_key comes from the
  # Cross-Dataset Integration section, which must already have run
  "cruise_key must be resolved on nearly every bottle" = n_ck > 0.99 * n_btl)
cat(glue("sample: {format(n_cast, big.mark=',')} casts / {format(n_btl, big.mark=',')} bottles ",
         "({round(100 * n_ck / max(n_btl, 1), 2)}% with cruise_key); ",
         "{format(n_bd, big.mark=',')} bottom_depth rows"), "\n")

# serve the retired per-dataset table names as VIEWs over the core, so
# in-notebook consumers (casts_derived, the mismatch collectors) and ad-hoc
# queries keep working against the old names. The real tables are DROPped rather
# than kept as `_src`: bottle_measurement is 11M rows and the wrangling DB is
# file-backed, so retaining a second copy is not free.
compat <- c(
  casts = "
    SELECT CAST(split_part(s.sample_key, ':', 3) AS BIGINT) AS cast_id,
           s.site_key, s.grid_key, s.cruise_key, s.order_occ,
           s.latitude, s.longitude, s.datetime AS datetime_start_utc, s.geom
    FROM sample s
    WHERE s.dataset_key = 'calcofi_bottle' AND s.sample_type = 'cast'",
  bottle = "
    SELECT CAST(split_part(s.sample_key, ':', 3) AS BIGINT) AS bottle_id,
           CAST(split_part(s.parent_sample_key, ':', 3) AS BIGINT) AS cast_id,
           s.site_key, s.depth_min_m AS depth_m
    FROM sample s
    WHERE s.dataset_key = 'calcofi_bottle' AND s.sample_type = 'bottle'",
  cast_condition = "
    SELECT sample_measurement_id AS cast_condition_id,
           CAST(split_part(sample_key, ':', 3) AS BIGINT) AS cast_id,
           measurement_type AS condition_type, measurement_value AS condition_value
    FROM sample_measurement
    WHERE dataset_key = 'calcofi_bottle'",
  bottle_measurement = "
    SELECT obs_id AS bottle_measurement_id,
           CAST(split_part(sample_key, ':', 3) AS BIGINT) AS bottle_id,
           measurement_type, measurement_value, measurement_qual, measurement_prec
    FROM obs WHERE dataset_key = 'calcofi_bottle'")
for (nm in names(compat)) {
  # DROP has to know which it is: DuckDB refuses "DROP TABLE" on a view (and
  # vice versa), and a re-run inside one session finds the view already there
  t <- dbGetQuery(con, glue(
    "SELECT table_type FROM information_schema.tables WHERE table_name = '{nm}'"))
  if (nrow(t)) {
    kind <- if (grepl("VIEW", t$table_type[1], ignore.case = TRUE)) "VIEW" else "TABLE"
    invisible(dbExecute(con, glue('DROP {kind} IF EXISTS "{nm}"')))
  }
  invisible(dbExecute(con, glue("CREATE OR REPLACE VIEW {nm} AS {compat[[nm]]}")))
}
cat(glue("compat views over core: {paste(names(compat), collapse = ', ')}"), "\n")
```
