1 Overview

Source: EDI package knb-lter-cce.54.10 (Goericke), entity ParticulateOrganicCarbonandNitrogen (table_54.csv): 17,413 rows, 18 columns, 73 cruises from 2004-11 to 2023-04. Fetched by libs/download_poc_pon.R, revision and md5 pinned. Licence: CC0 1.0 (the EML’s intellectualRights).

  • Provider: cce-lter (same as iron, euphausiids, picoplankton-bacteria).
  • Grain: one row per Niskin bottle water sample, filtered for POC/PON. The source’s own (studyName, Cast Number, Bottle Number) is the natural key, asserted unique after the clean-up below.
  • Realm: env. Two measurements are published per sample: poc (umol/L_C) and pon (umol/L_N), both in µmol/L.
  • Not published (derivable or held, kept in the archived source): ug_CperL and ug_NperL (the same values in µg/L; the notebook asserts the conversion), C/N ratio and C/N molar ratio (ratios of the published values, also asserted), Associated Bottle Number (meaning unconfirmed, Q03) and Notes (free text on 12 rows, Q05).
  • Cleaned before publishing (each counted and asserted below):
    • 4 rows that repeat another row in every column are dropped (2019-11 cast 25, Q02).
    • 2 rows share a sample key but give different depths (2005-11 cast 25 bottle 20, 1 m vs 2 m, identical values) and are held out until Q02 is answered.
    • 10 rows with no depth are held out (Q04): depth is a coordinate in the core.
  • Cruise key: from the ship code in studyName plus the source’s own Cruise designation (YYYYMM), resolved by derive_cruise_key_on_casts() (span, then source designation, then month).
  • Bottle match (evidence only): each sample is matched to its calcofi_bottle cast by site_key within 1 day, then to the Niskin bottle nearest its depth within 2 m. The match is reported, not published, and not set as parent_sample_key, following the cetacean eDNA decision (Ben, 2026-10-04): every sample is a root.

4 Clean, Type-Cast

Three clean-up steps, each counted and asserted against what the source held on 2026-10-06, so a new revision that changes any of them stops the render:

  1. Exact duplicates. 4 rows repeat another row in every column (2019-11 cast 25, bottles 16, 17, 20, 22). The copy is dropped (Q02).
  2. Conflicting key. After that, one key is still listed twice: 2005-11 cast 25 bottle 20, at 2 m and at 1 m with identical values. Both rows are held out (not published) until the provider says which depth is right (Q02).
  3. No depth. 10 rows have an empty Depth (m). They are held out (Q04): depth is a coordinate in the core and is never guessed.

Every measurement is blank-or-numeric with no sentinel: the EML declares -999 for Depth, and the file uses none (asserted).

4.1 Derived columns agree with the published ones

The µg/L columns and both ratios are not published because they follow from poc and pon. That is only safe if they really do, so it is checked here: µg/L is µmol/L times the atomic weight (C 12.0107, N 14.0067), and the ratios are C/N in µg and in µmol.

## Overview

**Source**: EDI package `knb-lter-cce.54.10` (Goericke), entity
*ParticulateOrganicCarbonandNitrogen* (`table_54.csv`): 17,413 rows, 18 columns,
73 cruises from 2004-11 to 2023-04. Fetched by `libs/download_poc_pon.R`, revision and md5 pinned.
Licence: CC0 1.0 (the EML's `intellectualRights`).

- **Provider**: `cce-lter` (same as `iron`, `euphausiids`, `picoplankton-bacteria`).
- **Grain**: one row per Niskin bottle water sample, filtered for POC/PON. The
  source's own `(studyName, Cast Number, Bottle Number)` is the natural key,
  asserted unique after the clean-up below.
- **Realm**: `env`. Two measurements are published per sample: `poc`
  (`umol/L_C`) and `pon` (`umol/L_N`), both in µmol/L.
- **Not published** (derivable or held, kept in the archived source):
  `ug_CperL` and `ug_NperL` (the same values in µg/L; the notebook asserts the
  conversion), `C/N ratio` and `C/N molar ratio` (ratios of the published values,
  also asserted), `Associated Bottle Number` (meaning unconfirmed, Q03) and
  `Notes` (free text on 12 rows, Q05).
- **Cleaned before publishing** (each counted and asserted below):
  - 4 rows that repeat another row in every column are dropped (2019-11 cast 25,
    Q02).
  - 2 rows share a sample key but give different depths (2005-11 cast 25 bottle
    20, 1 m vs 2 m, identical values) and are held out until Q02 is answered.
  - 10 rows with no depth are held out (Q04): depth is a coordinate in the core.
- **Cruise key**: from the ship code in `studyName` plus the source's own
  `Cruise` designation (YYYYMM), resolved by `derive_cruise_key_on_casts()`
  (span, then source designation, then month).
- **Bottle match** (evidence only): each sample is matched to its
  `calcofi_bottle` cast by `site_key` within 1 day, then to the Niskin bottle
  nearest its depth within 2 m. The match is reported, not published, and not set
  as `parent_sample_key`, following the cetacean eDNA decision (Ben,
  2026-10-04): every sample is a root.

## Resolve Ship and Cruise Keys

Same approach as the iron and picoplankton-bacteria notebooks: the trailing
token of `studyName` is the ship's NODC code (`2004-11-02-C-33RR` -> `33RR`).
Unlike iron, this source also ships the cruise's own `Cruise` designation
(YYYYMM), which differs from the start month in `studyName` on 3,023 rows (a
cruise that starts late in the month before its designated one), so it is passed
as `cruise_ym_col`.

```{r}
#| label: resolve-keys
load_prior_tables(
  con, parquet_dir = cc_stage_path("parquet", "swfsc_ichthyo"),
  gcs_prefix = "ingest/swfsc_ichthyo",  # public GCS copy when not staged locally
  tables = c("ship", "cruise"), as_view = TRUE)

dbExecute(con, "ALTER TABLE poc_sample ADD COLUMN IF NOT EXISTS ship_code VARCHAR")
dbExecute(con, "UPDATE poc_sample SET ship_code = regexp_extract(study_name, '[0-9A-Z]+$')")

# CCE-LTER labels recent ships with CalCOFI's own codes (325S, 33SR, 33RL, 31OS,
# 32BH), not the NODC codes the ship reference uses (3322, 33P4, 33UD, 32I1,
# 39C2). metadata/ship_renames.csv holds that code -> NODC crosswalk. It is
# applied by code alone: derive_cruise_key_on_casts() matches renames on code +
# ship name, and this source has no ship name, so without this step those
# cruises get no cruise_key (first render, 2026-10-06: 7,717 of 17,397 POC samples).
d_ship_xw <- read_csv(here("metadata/ship_renames.csv"), col_types = cols(.default = "c")) |>
  distinct(csv_code, csv_code_new) |>
  filter(csv_code != csv_code_new)
stopifnot("each ship code in ship_renames.csv maps to one NODC code" =
            !anyDuplicated(d_ship_xw$csv_code))
dbWriteTable(con, "_ship_code_xw", as.data.frame(d_ship_xw), overwrite = TRUE)
dbGetQuery(con, "
  SELECT s.ship_code AS source_code, x.csv_code_new AS nodc_code, COUNT(*) AS n
  FROM poc_sample s JOIN _ship_code_xw x ON s.ship_code = x.csv_code
  GROUP BY 1, 2 ORDER BY 1") |>
  datatable(caption = "Ship codes translated to NODC (metadata/ship_renames.csv)", rownames = FALSE)
dbExecute(con, "
  UPDATE poc_sample SET ship_code = x.csv_code_new
  FROM _ship_code_xw x WHERE poc_sample.ship_code = x.csv_code")

cruise_key_result <- derive_cruise_key_on_casts(
  con, table_name = "poc_sample", datetime_col = "datetime_start_utc",
  cruise_ym_col = "cruise_ym")
cruise_key_result$key_stats |>
  datatable(caption = "cruise_key resolution: span > source designation > month")

n_ck  <- dbGetQuery(con, "SELECT COUNT(*) FROM poc_sample WHERE cruise_key IS NOT NULL")[[1]]
n_all <- dbGetQuery(con, "SELECT COUNT(*) FROM poc_sample")[[1]]
cat(glue("cruise_key match: {n_ck}/{n_all} ({round(100*n_ck/n_all,1)}%)"), "\n")
stopifnot("every sample resolves a cruise_key (an unmatched ship code needs a row in metadata/ship_renames.csv)" =
            n_ck == n_all)
```

## Match to calcofi_bottle (evidence only)

Each sample is matched to the `calcofi_bottle` cast at the same `site_key`
within 1 day (`match_by_site_datetime()`), then to the Niskin bottle on that
cast nearest its depth within 2 m (`match_nearest_by_depth()`). The match rate is
reported, not asserted: the bottle database may not yet hold the most recent
cruises. The matched bottle is kept on `poc_sample` (`bottle_sample_key`) as
evidence only. It is not published and not set as `parent_sample_key`.

