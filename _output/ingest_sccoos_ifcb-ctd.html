1 Overview

Source: a summary table built by Vivian (Lin) Hou (SIO) for Andy Allen’s IFCB program (JCVI / SIO; the images are hosted on the CalOOS IFCB dashboard, ifcb.caloos.org, which is why the dataset key is sccoos_ifcb-ctd – the key was minted from the host when the holding was created, see below) from Imaging FlowCytobot (IFCB) bins run on water collected from the CalCOFI CTD rosette, Aug 2022 - Jul 2026 (10 cruises, 671 bins). Supplied as four files in data-public/sccoos/ifcb-ctd/:

  • CalCOFI_CTD_IFCB_data_summary_new.xlsx – the data: sheet summary (one row per bin x taxon x ESD size class), plus class_to_WoRMS (the autoclass class -> WoRMS crosswalk) and per_bin_totals (a per-bin check table).
  • CalCOFI_CTD_metadata_filled_102226.csv – the per-bin cast metadata, with the provider’s own skip flags.
  • CalCOFI_IFCB_WoRMS_match.xlsx – the provider’s WoRMS naming table.
  • IFCB_CalCOFI_summary.ipynb – the provider’s notebook that builds the summary. Read for units and method (see below), archived, not executed.

What a row is. An IFCB images the cells in a measured volume of water, an image classifier (the “autoclass”) assigns each image to a class, and the summary groups the classified images by taxon and by equivalent spherical diameter (ESD) size class. Per the provider’s notebook: Count is the number of images (cells) in the group, Abundance_counts_per_ml is Count / Volume_ml, Volume_ml is 0.25 ml/min x (runTime - inhibitTime) / 60, Avg_Biovol is the mean cell biovolume in um3 and Avg_ESD the mean ESD in um (pixels converted at 3.4 px/um). The summary keeps cells only (bubbles, detritus, beads and other non-cell classes are filtered upstream, class_to_WoRMS Cell (yes/no)).

Taxon columns (provider, 2026-10-30): Autoclass_classes are the IFCB classifier’s own class names; several classes can be combined into one Taxa (|-separated in Autoclass_classes); Taxa is checked against WoRMS and WoRMS_matched_name is the valid WoRMS name, written with _ for a space.

Source revision 2026-10-30. Vivian Hou re-issued the summary after Rasmus Swalethorp’s review (2026-10-28): headers use _ (Depthstype -> Sample_type, Sizerange ESD -> Size_range_ESD, Abundance (counts/ml) -> Abundance_counts_per_ml, …), taxon names use _ for a space (unidentified cells -> unidentified_cells), multi-value cells are no longer ;-joined, sample types are surface / chla max, and Date and Sample_time_UTC are new. The counts are unchanged (the same 671 bins, 104 taxa and 530,927 images; per_bin_totals reproduces). Positions changed in two ways. Ten 2504SH bins on lines 76.7 and 63.3 were corrected: the earlier summary (and the metadata CSV) gave all ten the position of station 80 100, and the re-issue gives each its own station’s position. Two 2601LS bins (line 63.3, stations 80 and 90) lost their Latitude / Longitude; those two are taken from the same bins’ rows of the metadata CSV, which match the earlier summary and the other bin of each cast (Read Source Data; Q16).

Cleaned before ingest (B. Huang, 2026-11-01). The file in the dataset folder is the provider’s re-issue with four formatting fixes and no value changes: Sample_type ‘chl a max’ -> ‘chla max’ (1 bin, 67 rows; the other 322 DCM bins use ‘chla max’); Taxa / WoRMS_matched_name ‘Navicula_’ -> ‘Navicula’ (a stray trailing _, formerly a trailing space); Autoclass_classes and Autoclass_Accuracy joined with | instead of , (7,991 rows; a comma inside a cell breaks a CSV export); and the class_to_WoRMS headers given _ (WoRMS_matched_name, WoRMS_status, Cell_yes_no), its ‘Navicula’ trimmed.

Sample grain is the IFCB bin (IFCB_filename, DYYYYMMDDTHHMMSS_IFCBnnn, the UTC start of the run): one water sample from one CTD bottle, run once. Every row of a bin shares one cruise, position, depth and analysed volume (asserted below). The bin id carries the UTC timestamp, so datetime comes from the filename and is checked against the provider’s Sample_time_UTC and Sample_time_PT.

Three grains in the core model (the size class is a third dimension that no single obs row can carry):

  • obs: one row per bin x taxon x measurement_type, summed over the size classes: ifcb_abundance (cells/ml) and ifcb_biovolume (um3/ml, the total cell biovolume per ml, sum(Count x Avg Biovol) / Volume_ml).
  • obs_attribute: the size-class split behind each headline, one row per bin x taxon x size class, bin_label the class (<10, 10-20, 20-40, 40> um) and count the cells imaged in that class. Counts sum to the headline x volume (asserted).
  • sample_measurement: ifcb_volume_analyzed (ml), the denominator.

Not published (still in the archived source): the per-size-class mean and SD of biovolume and ESD, Autoclass_Accuracy (the provider’s manual check of classifier v1, accurate cells / cells assigned, per autoclass class: a per-class figure, not a per-image confidence – Q06), the autoclass class names merged into each taxon, Date, and the bottle number. The bin is not linked to its bottle sample yet (parent_sample_key is NULL, Q08).

Detections only. The summary lists the taxa seen in a bin; a taxon absent from a bin has no row, and a 0 is never emitted. Absence cannot be inferred (Q09).

6 Standardize Taxonomy

The summary already carries a resolved WoRMS AphiaID for every taxon that has one (the provider matched names against WoRMS, CalCOFI_IFCB_WoRMS_match.xlsx), so there is no name-matching to do: the AphiaID is declared as worms_id and the package resolves and checks it. The one exception is unidentified_cells: in the provider’s table the four classes nanoplankton_mix, flagellate, colony and coccolithophorid all map to this one name with no AphiaID (the single largest group, 37% of all images; Q03). It is not a taxon, so it takes a dataset-local taxon_key by declaration, one key at a time, the same mechanism ZooScan’s others and picoplankton’s picoeukaryotes use (also declared in release_database.qmd’s TAXON_LOCAL_ALLOW, which is the gate that fails the release).

One consequence of keying by AphiaID: the provider’s Hemiaulus (worms:605114) is unaccepted in WoRMS and resolves to Eucampia (worms:149130), which the provider also has as its own class. Both codes stay in dataset_taxon, but they share one taxon_key, so the aggregation below sums them in the 26 bins that carry both (Q10).

ds_taxa_code is the source’s taxon name verbatim (the source now writes _ for a space, so unidentified_cells and the minted key sccoos_ifcb-ctd:unidentified_cells agree).

## Overview

**Source**: a summary table built by Vivian (Lin) Hou (SIO) for Andy Allen's
IFCB program (JCVI / SIO; the images are hosted on the CalOOS IFCB dashboard,
`ifcb.caloos.org`, which is why the dataset key is `sccoos_ifcb-ctd` -- the key was
minted from the host when the holding was created, see below) from Imaging
FlowCytobot (IFCB) bins run on water collected from the CalCOFI CTD rosette, Aug
2022 - Jul 2026 (10 cruises, 671 bins). Supplied as four files in
`data-public/sccoos/ifcb-ctd/`:

- `CalCOFI_CTD_IFCB_data_summary_new.xlsx` -- the data: sheet `summary` (one row
  per bin x taxon x ESD size class), plus `class_to_WoRMS` (the autoclass
  class -> WoRMS crosswalk) and `per_bin_totals` (a per-bin check table).
- `CalCOFI_CTD_metadata_filled_102226.csv` -- the per-bin cast metadata, with
  the provider's own `skip` flags.
- `CalCOFI_IFCB_WoRMS_match.xlsx` -- the provider's WoRMS naming table.
- `IFCB_CalCOFI_summary.ipynb` -- the provider's notebook that builds the
  summary. Read for units and method (see below), archived, not executed.

**What a row is.** An IFCB images the cells in a measured volume of water, an
image classifier (the "autoclass") assigns each image to a class, and the
summary groups the classified images by taxon and by equivalent spherical
diameter (ESD) size class. Per the provider's notebook: `Count` is the number
of images (cells) in the group, `Abundance_counts_per_ml` is `Count / Volume_ml`,
`Volume_ml` is `0.25 ml/min x (runTime - inhibitTime) / 60`, `Avg_Biovol` is the
mean cell biovolume in um3 and `Avg_ESD` the mean ESD in um (pixels converted at
3.4 px/um). The summary keeps cells only (bubbles, detritus, beads and other
non-cell classes are filtered upstream, class_to_WoRMS `Cell (yes/no)`).

**Taxon columns** (provider, 2026-10-30): `Autoclass_classes` are the IFCB
classifier's own class names; several classes can be combined into one `Taxa`
(`|`-separated in `Autoclass_classes`); `Taxa` is checked against WoRMS and
`WoRMS_matched_name` is the valid WoRMS name, written with `_` for a space.

**Source revision 2026-10-30.** Vivian Hou re-issued the summary after Rasmus
Swalethorp's review (2026-10-28): headers use `_` (`Depthstype` -> `Sample_type`,
`Sizerange ESD` -> `Size_range_ESD`, `Abundance (counts/ml)` ->
`Abundance_counts_per_ml`, ...), taxon names use `_` for a space
(`unidentified cells` -> `unidentified_cells`), multi-value cells are no longer
`; `-joined, sample types are `surface` / `chla max`, and `Date` and
`Sample_time_UTC` are new. The counts are unchanged (the same 671 bins, 104
taxa and 530,927 images; `per_bin_totals` reproduces). Positions changed in
two ways. Ten 2504SH bins on lines 76.7 and 63.3 were corrected: the earlier
summary (and the metadata CSV) gave all ten the position of station 80 100,
and the re-issue gives each its own station's position. Two 2601LS bins (line
63.3, stations 80 and 90) lost their `Latitude` / `Longitude`; those two are
taken from the same bins' rows of the metadata CSV, which match the earlier
summary and the other bin of each cast (Read Source Data; Q16).

**Cleaned before ingest (B. Huang, 2026-11-01).** The file in the dataset folder
is the provider's re-issue with four formatting fixes and no value changes:
`Sample_type` 'chl a max' -> 'chla max' (1 bin, 67 rows; the other 322 DCM bins
use 'chla max'); `Taxa` / `WoRMS_matched_name` 'Navicula_' -> 'Navicula' (a
stray trailing `_`, formerly a trailing space); `Autoclass_classes` and
`Autoclass_Accuracy` joined with `|` instead of `, ` (7,991 rows; a comma inside
a cell breaks a CSV export); and the `class_to_WoRMS` headers given `_`
(`WoRMS_matched_name`, `WoRMS_status`, `Cell_yes_no`), its 'Navicula ' trimmed.

**Sample grain is the IFCB bin** (`IFCB_filename`, `DYYYYMMDDTHHMMSS_IFCBnnn`,
the UTC start of the run): one water sample from one CTD bottle, run once. Every
row of a bin shares one cruise, position, depth and analysed volume (asserted
below). The bin id carries the UTC timestamp, so `datetime` comes from the
filename and is checked against the provider's `Sample_time_UTC` and
`Sample_time_PT`.

**Three grains in the core model** (the size class is a third dimension that no
single `obs` row can carry):

- `obs`: one row per bin x taxon x measurement_type, **summed over the size
  classes**: `ifcb_abundance` (cells/ml) and `ifcb_biovolume` (um3/ml, the
  total cell biovolume per ml, `sum(Count x Avg Biovol) / Volume_ml`).
- `obs_attribute`: the size-class split behind each headline, one row per bin x
  taxon x size class, `bin_label` the class (`<10`, `10-20`, `20-40`, `40>` um)
  and `count` the cells imaged in that class. Counts sum to the headline x
  volume (asserted).
- `sample_measurement`: `ifcb_volume_analyzed` (ml), the denominator.

Not published (still in the archived source): the per-size-class mean and SD of
biovolume and ESD, `Autoclass_Accuracy` (the provider's manual check of
classifier v1, accurate cells / cells assigned, per autoclass class: a per-class
figure, not a per-image confidence -- Q06), the autoclass class names merged
into each taxon, `Date`, and the bottle number. The bin is **not** linked to its
`bottle` sample yet (parent_sample_key is NULL, Q08).

**Detections only.** The summary lists the taxa seen in a bin; a taxon absent
from a bin has no row, and a 0 is never emitted. Absence cannot be inferred
(Q09).

## Standardize Taxonomy

The summary already carries a resolved WoRMS AphiaID for every taxon that has
one (the provider matched names against WoRMS, `CalCOFI_IFCB_WoRMS_match.xlsx`),
so there is no name-matching to do: the AphiaID is declared as `worms_id` and the
package resolves and checks it. The one exception is **`unidentified_cells`**:
in the provider's table the four classes `nanoplankton_mix`, `flagellate`,
`colony` and `coccolithophorid` all map to this one name with no AphiaID (the
single largest group, 37% of all images; Q03). It is not a taxon, so it takes a dataset-local `taxon_key` by
declaration, one key at a time, the same mechanism ZooScan's `others` and
picoplankton's `picoeukaryotes` use (also declared in `release_database.qmd`'s
`TAXON_LOCAL_ALLOW`, which is the gate that fails the release).

One consequence of keying by AphiaID: the provider's `Hemiaulus` (worms:605114)
is `unaccepted` in WoRMS and resolves to `Eucampia` (worms:149130), which the
provider also has as its own class. Both codes stay in `dataset_taxon`, but they
share one `taxon_key`, so the aggregation below sums them in the 26 bins that
carry both (Q10).

`ds_taxa_code` is the source's taxon name verbatim (the source now writes `_`
for a space, so `unidentified_cells` and the minted key
`sccoos_ifcb-ctd:unidentified_cells` agree).

## Aggregate to Bin x Taxon

The headline grain is bin x taxon, **summed over the four size classes**. The
taxon is the resolved `taxon_key`, so provider classes that resolve to one taxon
are summed together (Hemiaulus into Eucampia, below).
Biovolume concentration is `sum(count x mean biovolume) / volume`: the summary
carries a per-class mean cell biovolume, so the class total is `count x mean` and
the taxon total is their sum.

```{r}
#| label: aggregate

dbWriteTable(con, "ifcb_summary",
             d_sum |> mutate(ds_taxa_code = taxa) |> as.data.frame(),
             overwrite = TRUE)

# Group by the RESOLVED taxon_key, not the provider's class name. Two provider
# classes can resolve to one taxon: the package replaces an unaccepted WoRMS id
# with the accepted one, and WoRMS lists provider class `Hemiaulus` (worms:605114)
# as unaccepted -> `Eucampia` (worms:149130), which the provider also has as its
# own class. In the 26 bins that carry both, their counts, abundance and
# biovolume are summed into the one Eucampia taxon (Q10). The source stays
# unchanged; dataset_taxon still maps both provider codes to the one key.
dbExecute(con, glue("
  CREATE OR REPLACE TABLE ifcb_bin_taxon AS
  SELECT x.ifcb_filename, dt.taxon_key,
         SUM(x.n_cells)                             AS n_cells,
         SUM(x.abundance_ml)                        AS abundance_ml,
         SUM(x.n_cells * x.avg_biovol_um3) / ANY_VALUE(x.volume_ml) AS biovolume_ml,
         COUNT(DISTINCT x.size_class)               AS n_size_class,
         COUNT(DISTINCT x.ds_taxa_code)             AS n_source_class
  FROM ifcb_summary x
  JOIN dataset_taxon dt ON dt.dataset_key = '{ds_key}'
                       AND dt.ds_taxa_code = x.ds_taxa_code
  GROUP BY x.ifcb_filename, dt.taxon_key"))

# the size-class split on the same grain (bin x taxon_key x size class)
dbExecute(con, glue("
  CREATE OR REPLACE TABLE ifcb_size_taxon AS
  SELECT x.ifcb_filename, dt.taxon_key, x.size_class, SUM(x.n_cells) AS n_cells
  FROM ifcb_summary x
  JOIN dataset_taxon dt ON dt.dataset_key = '{ds_key}'
                       AND dt.ds_taxa_code = x.ds_taxa_code
  GROUP BY x.ifcb_filename, dt.taxon_key, x.size_class"))

d_bt <- dbGetQuery(con, "SELECT * FROM ifcb_bin_taxon")
n_size_taxon <- dbGetQuery(con, "SELECT COUNT(*) FROM ifcb_size_taxon")[[1]]
stopifnot(
  "ifcb_bin_taxon must be unique per bin x taxon_key" =
    !anyDuplicated(d_bt[, c("ifcb_filename", "taxon_key")]),
  "every source row must resolve a taxon_key" = !anyNA(d_bt$taxon_key),
  "the aggregation must conserve every imaged cell" = sum(d_bt$n_cells) == sum(d_sum$n_cells),
  "abundance conserved over the aggregation" =
    abs(sum(d_bt$abundance_ml) - sum(d_sum$abundance_ml)) < 1e-6,
  "no negative biovolume" = all(d_bt$biovolume_ml >= 0),
  "every bin x taxon must have 1-4 size classes" = all(d_bt$n_size_class %in% 1:4),
  "size-class cells conserved on the taxon_key grain" =
    dbGetQuery(con, "SELECT SUM(n_cells) FROM ifcb_size_taxon")[[1]] == sum(d_sum$n_cells))

d_bt |>
  summarize(bin_x_taxon = n(), bins = n_distinct(ifcb_filename),
            taxa = n_distinct(taxon_key), cells = sum(n_cells),
            bins_with_merged_classes = sum(n_source_class > 1)) |>
  datatable(caption = "Aggregated headline grain (bin x taxon)", rownames = FALSE)
```

## Validate

```{r}
#| label: validate

results <- validate_for_release(con, checks = "all", strict = FALSE)

# validate_for_release()'s null check treats every *_id/_key column as required,
# a heuristic rather than this dataset's contract. Every nullable case is
# declared here with its reason; anything not on the list is a hard failure.
# `n` is the count the reason was derived for. NA_integer_ = the reason is known
# but the count has not been pinned yet: it is PRINTED, not failed on. Pin the
# NA rows after the first render, then a moved count becomes a hard failure.
nullable <- tribble(
  ~table,         ~column,             ~n,            ~reason,
  "ifcb_summary", "aphia_id",          1408L,         "staging table, not published: the rows of the 'unidentified_cells' class carry no AphiaID by design (Q03)",
  "sample",       "parent_sample_key", n_bin,         "a bin is a root event: not yet linked to the CTD bottle it was drawn from (provider question Q08)",
  "taxon",        "worms_id",          1L,            "the dataset-local 'unidentified_cells' class is not a taxon and has no WoRMS id (Q03)",
  "taxon",        "itis_id",           125L,          "WoRMS links no ITIS TSN for these nodes",
  "taxon",        "gbif_id",           291L,          "nothing asks GBIF -- no GBIF crosswalk in the xref",
  "taxon",        "ncbi_id",           291L,          "never populated by ANY dataset",
  "taxon",        "inat_id",           291L,          "never populated by ANY dataset",
  "taxon",        "parent_taxon_key",  5L,            "the root of a lineage has no parent")

nulls <- results$checks |>
  filter(check == "nulls", status == "error") |>
  mutate(column = str_match(message, "column '([^']+)'")[, 2],
         n      = as.integer(str_match(message, "has (\\d+) NULL")[, 2])) |>
  select(table, column, n)

reconciled  <- full_join(nulls, nullable |> select(table, column, n_expected = n),
                         by = c("table", "column"))
declared    <- nullable |> select(table, column)
unexplained <- reconciled |> anti_join(declared, by = c("table", "column"))
moved       <- reconciled |> filter(!is.na(n_expected), !is.na(n), n != n_expected)
to_pin      <- reconciled |> semi_join(declared, by = c("table", "column")) |>
  filter(is.na(n_expected), !is.na(n))
resolved    <- reconciled |> semi_join(declared, by = c("table", "column")) |>
  filter(is.na(n))
other_fail  <- results$checks |> filter(check != "nulls", status == "error")
if (nrow(unexplained)) print(unexplained)
if (nrow(moved))       print(moved)
if (nrow(other_fail))  print(other_fail)
if (nrow(to_pin))      { cat("pin these counts in `nullable`:\n"); print(to_pin) }
stopifnot(
  "a NULL appeared in a column with no declared reason" = nrow(unexplained) == 0,
  "a declared NULL count has changed -- the data moved, re-derive the reason" = nrow(moved) == 0,
  "a validate_for_release() check other than nulls failed" = nrow(other_fail) == 0)
if (nrow(resolved))
  cat(glue("{nrow(resolved)} declared nullable case(s) no longer occur -- prune them: ",
           "{paste(resolved$table, resolved$column, sep = '.', collapse = ', ')}"), "\n")
if (length(results$warnings) > 0)
  cat("Warnings:\n", paste("-", results$warnings, collapse = "\n"), "\n")

cat(glue("validate_for_release: {ifelse(results$passed, 'PASSED', 'FAILED')} on its null ",
         "heuristic; {nrow(nulls)} null case(s) reconciled against {nrow(nullable)} declared, ",
         "{nrow(unexplained)} unexplained, {nrow(other_fail)} other failures"), "\n")
```
