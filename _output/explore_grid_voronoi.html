1 Why, and where this stands

Ben, 2026-10-02 (CalCOFI/workflows#130): a grid point, i.e. a site (x: station, y: line), must land on its line, and the grid has slivers (the calcofi4r “CalCOFI grid” figure; related #86 and CalCOFI/db-viz-station#19). Rather than patch, start from the official station positions and build the cells as a Voronoi tessellation of them.

The first version of this page (2026-10-02) compared that idea (Option A) with two repairs of the previous grid. On 2026-10-04 Ben decided that Option A ships in the next database release. The cells are now built by calcofi4r::cc_grid_build() and bundled as calcofi4r::cc_grid; calcofi4db::assign_grid_key() keys a position to a cell, and the release publishes a grid_crosswalk table. This page is the evidence pack for that implementation: the six gates an independent review set (Section 9), each measured here on the promoted release v2026.10.01, and the same headline numbers for one variant (no SCCOOS inshore cells) to put beside it at the 2026-10-08 meeting.

This is an exploration, not an ingest. It has no calcofi: block, like every other explore_*.qmd, so build_targets_list() never sees it: it is not a target, not a release input, and it writes nothing to cc_stage_dir(). It changes no grid_key. It reads the published release v2026.10.01 (the local copy under cc_stage_dir()/releases/ when there is one) and writes only this page.

# polygon parts of a keyed sf, with area (km²) and mean width 2A/P (km)
split_parts <- function(x, key = "grid_key") {
  p <- x |> select(all_of(key)) |> st_cast("MULTIPOLYGON") |> st_cast("POLYGON", warn = FALSE)
  p$area_km2 <- as.numeric(st_area(p)) / 1e6
  p$width_km <- 2 * p$area_km2 / (as.numeric(st_length(st_cast(st_geometry(p), "MULTILINESTRING"))) / 1000)
  p |> group_by(across(all_of(key))) |>
    mutate(part = row_number(), n_parts = n(), largest = area_km2 == max(area_km2)) |> ungroup()
}
# a part is a sliver when it does not hold its cell's generator (the station it is the cell of)
# and it is thin or small
flag_slivers <- function(parts, gen, key = "grid_key") {
  hit <- mapply(function(p, k) {
    gi <- which(gen[[key]] == k); length(gi) && st_intersects(p, st_geometry(gen)[gi], sparse = FALSE)[1, 1]
  }, st_geometry(parts), parts[[key]])
  parts$holds_gen <- hit
  parts$sliver    <- !hit & (parts$width_km < SLIVER_W | parts$area_km2 < SLIVER_A)
  # a sliver touching another cell is the visible defect; one touching none is a pocket of
  # water the land mask cuts off (a lagoon, a harbour)
  nb <- st_is_within_distance(parts, parts, 50)
  parts$touches_other <- mapply(function(i, k) any(parts[[key]][i] != k), nb, parts[[key]])
  parts
}
# absorb every sliver into the neighbouring cell it shares the longest edge with,
# smallest first; a sliver with no neighbour keeps its key (reported)
absorb_slivers <- function(parts, key = "grid_key", tol_m = 50) {
  parts$key_new  <- parts[[key]]
  parts$shared_m <- NA_real_
  for (pid in order(parts$area_km2)) {
    if (!parts$sliver[pid]) next
    me     <- parts[pid, ]
    others <- which(parts$key_new != me$key_new)
    cand   <- others[st_intersects(st_buffer(st_geometry(me), tol_m), st_geometry(parts)[others], sparse = FALSE)[1, ]]
    if (!length(cand)) next
    bnd <- st_boundary(st_geometry(me))
    len <- vapply(cand, function(j) {
      x <- st_intersection(bnd, st_buffer(st_geometry(parts)[j], tol_m))
      if (!length(x) || all(st_is_empty(x))) 0 else sum(as.numeric(st_length(x)))
    }, numeric(1))
    if (max(len) <= 0) next
    parts$key_new[pid]  <- parts$key_new[cand[which.max(len)]]
    parts$shared_m[pid] <- max(len)
  }
  parts
}
# the cell a point falls in, in metres (the key that sorts first on a tie, as cc_grid_key())
first_hit <- function(pts, cells, key = "grid_key") {
  ix <- st_intersects(pts, cells)
  vapply(ix, function(i) if (length(i)) sort(cells[[key]][i], method = "radix")[1] else NA_character_, "")
}

2 How the previous grid was built

The release’s grid table through v2026.10.01 (218 cells) is calcofi4r::cc_grid as it was through calcofi4r 1.24.2, kept now as calcofi4r::cc_grid_v1, with each cell named st{station}-ln{line} (_hist for the historical pattern). Every ingest calls calcofi4db::assign_grid_key(), a point-in-polygon test of the sample’s position against those cells, so grid_key on sample and obs is wherever the position falls.

That grid came from calcofi4r/data-raw/cc_grid_v1.R, which:

  1. lays three idealized lattices in +proj=calcofi (line, station) coordinates, not the occupied positions: 5-unit spacing for stations ≤ 60 on the standard lines, 10-unit spacing offshore to station 120, and a 20-unit historical lattice out to the convex hull of every CTD cast;
  2. takes a Voronoi tessellation of each lattice (in line/station units), cuts the finer ones out of the coarser, and hand-merges six historical pairs (e.g. 55/80 from 50/80 + 60/80);
  3. keeps the cells listed in data-raw/cc_grid_sta-keys.csv and erases Natural Earth 10 m land (st_difference), which leaves gaps along the coast;
  4. glues five of those gaps back onto line 93.3 cells by hand (cc_grid_box4slivers.geojson, st_union onto 93.3,30 … 93.3,110), which is where the line-93.3 cells pick up second, detached parts;
  5. makes the site of each cell st_centroid(geom, of_largest_polygon = TRUE) on lon/lat (cc_grid_ctrs; the release’s grid.geom_ctr).

So a site was the centroid of whatever polygon survived steps 2–4, never a station position: that is why sites left their line wherever land, a merge or a glued gap reshaped the cell. And the lattice is nominal (35, 40, 45, 50 …) while the occupied stations are not (90.0 37, 90.0 53, 80.0 51, 83.3 39.4 …), which is why an inshore cell held several real stations.

5 The shipped grid: Voronoi of the official positions

calcofi4r::cc_grid is cc_grid_build(cc_station_positions, cc_grid_v1, cc_grid_land) (calcofi4r/data-raw/cc_grid.R, no hand edits). The rules, as the function documents them:

  1. Extent. The outer hull of the previous grid (the union of its cells with interior holes filled) minus land. Water that land cuts off from every generator is not part of the grid.
  2. Generators. The 113 official positions, plus a seed for each previous cell whose labelled (line, station) lies more than 20 nautical miles outside the convex hull of the official stations, so the extended historical grid keeps its cells and keys. A seed is the cell’s label under +proj=calcofi, on land or not, so the edge it shares with its neighbours stays where the previous lattice put it. A previous cell inside the 20 nautical mile zone that is not a station is retired: its water goes to the nearest generator.
  3. Cells. The Voronoi tessellation in metres (California Albers, not line/station units, which weigh a line unit of 22.2 km and a station unit of 7.4 km alike), clipped to the extent, with a vertex every 5 km along each edge so the lon/lat polygon follows the metric edge.
  4. Pockets. A piece of a cell that land separates from the piece holding its station joins the neighbouring cell it shares the longest water edge with. A cell is then one polygon.
  5. Sites. A cell’s site (grid.geom_ctr) is its generator; for a seed on land, the previous cell’s centre when the new cell holds it, else a point on the cell.
  6. Attributes. A station’s cell is nearshore at station ≤ 60 and offshore beyond; standard on lines ≥ 76.7 (the 75-station pattern) and extended north of it; spacing class 5 nearshore, 10 offshore. A kept cell keeps the previous cell’s attributes and key.

The land is calcofi4r::cc_grid_land: OpenStreetMap land polygons (extract 2026-08-31) with islets under 1 km² dropped, the coastline pulled back 300 m and simplified to 100 m, so a ship at its berth or a nearshore position rounded to the minute still falls in a cell and the cells stay light enough for a browser.

How offshore cells are bounded. An official station on the edge of the pattern (station 100 to 120) is bounded seaward by the next historical seed, i.e. the 20-unit lattice, and finally by the previous outer hull, so an outer official cell reaches about halfway to the historical lattice beyond it.

## Why, and where this stands {#sec-why}

Ben, 2026-10-02 ([CalCOFI/workflows#130](https://github.com/CalCOFI/workflows/issues/130)):
a grid point, i.e. a **site** (x: station, y: line), must land on its line, and the grid has
**slivers** (the [calcofi4r "CalCOFI grid"
figure](https://calcofi.io/calcofi4r/articles/calcofi4r.html#calcofi-grid); related
[#86](https://github.com/CalCOFI/workflows/issues/86) and
[CalCOFI/db-viz-station#19](https://github.com/CalCOFI/db-viz-station/issues/19)). Rather than
patch, start from the [official station
positions](https://calcofi.org/sampling-info/station-positions/) and build the cells as a Voronoi
tessellation of them.

The first version of this page (2026-10-02) compared that idea (Option A) with two repairs of the
previous grid. **On 2026-10-04 Ben decided that Option A ships in the next database release.**
The cells are now built by `calcofi4r::cc_grid_build()` and bundled as `calcofi4r::cc_grid`;
`calcofi4db::assign_grid_key()` keys a position to a cell, and the release publishes a
`grid_crosswalk` table. This page is the **evidence pack** for that implementation: the six
gates an independent review set (@sec-gates), each measured here on the promoted release
v2026.10.01, and the same headline numbers for one variant (no SCCOOS inshore cells) to put
beside it at the 2026-10-08 meeting.

`explore_*.qmd`, so `build_targets_list()` never sees it: it is not a target, not a release

split_parts <- function(x, key = "grid_key") {
  p <- x |> select(all_of(key)) |> st_cast("MULTIPOLYGON") |> st_cast("POLYGON", warn = FALSE)

# a part is a sliver when it does not hold its cell's generator (the station it is the cell of)
# and it is thin or small
flag_slivers <- function(parts, gen, key = "grid_key") {
  hit <- mapply(function(p, k) {
    gi <- which(gen[[key]] == k); length(gi) && st_intersects(p, st_geometry(gen)[gi], sparse = FALSE)[1, 1]
  }, st_geometry(parts), parts[[key]])
  parts$holds_gen <- hit
  parts$sliver    <- !hit & (parts$width_km < SLIVER_W | parts$area_km2 < SLIVER_A)
  # a sliver touching another cell is the visible defect; one touching none is a pocket of
  # water the land mask cuts off (a lagoon, a harbour)
  nb <- st_is_within_distance(parts, parts, 50)
  parts$touches_other <- mapply(function(i, k) any(parts[[key]][i] != k), nb, parts[[key]])
  parts
}
# absorb every sliver into the neighbouring cell it shares the longest edge with,
# smallest first; a sliver with no neighbour keeps its key (reported)
absorb_slivers <- function(parts, key = "grid_key", tol_m = 50) {
  parts$key_new  <- parts[[key]]
  parts$shared_m <- NA_real_
  for (pid in order(parts$area_km2)) {
    if (!parts$sliver[pid]) next
    me     <- parts[pid, ]
    others <- which(parts$key_new != me$key_new)
    cand   <- others[st_intersects(st_buffer(st_geometry(me), tol_m), st_geometry(parts)[others], sparse = FALSE)[1, ]]
    if (!length(cand)) next
    bnd <- st_boundary(st_geometry(me))
    len <- vapply(cand, function(j) {
      x <- st_intersection(bnd, st_buffer(st_geometry(parts)[j], tol_m))
      if (!length(x) || all(st_is_empty(x))) 0 else sum(as.numeric(st_length(x)))
    }, numeric(1))
    if (max(len) <= 0) next
    parts$key_new[pid]  <- parts$key_new[cand[which.max(len)]]
    parts$shared_m[pid] <- max(len)
  }
  parts
}

## How the previous grid was built {#sec-today-build}

The release's `grid` table through v2026.10.01 (218 cells) is `calcofi4r::cc_grid` as it was
through calcofi4r 1.24.2, kept now as `calcofi4r::cc_grid_v1`, with each cell named
`st{station}-ln{line}` (`_hist` for the historical pattern). Every ingest calls
`calcofi4db::assign_grid_key()`, a point-in-polygon test of the sample's position against those
cells, so `grid_key` on `sample` and `obs` is wherever the position falls.

That grid came from `calcofi4r/data-raw/cc_grid_v1.R`, which:

1. lays three **idealized lattices** in `+proj=calcofi` (line, station) coordinates, not the
   occupied positions: 5-unit spacing for stations ≤ 60 on the standard lines, 10-unit spacing
   offshore to station 120, and a 20-unit historical lattice out to the convex hull of every
   CTD cast;
2. takes a Voronoi tessellation of each lattice (in line/station units), cuts the finer ones
   out of the coarser, and hand-merges six historical pairs (e.g. 55/80 from 50/80 + 60/80);
3. keeps the cells listed in `data-raw/cc_grid_sta-keys.csv` and erases Natural Earth 10 m land
   (`st_difference`), which leaves gaps along the coast;
4. glues five of those gaps back onto line 93.3 cells by hand (`cc_grid_box4slivers.geojson`,
   `st_union` onto `93.3,30` … `93.3,110`), which is where the line-93.3 cells pick up second,
   detached parts;
5. makes the site of each cell `st_centroid(geom, of_largest_polygon = TRUE)` on lon/lat
   (`cc_grid_ctrs`; the release's `grid.geom_ctr`).

So a site was the centroid of whatever polygon survived steps 2–4, never a station position:
that is why sites left their line wherever land, a merge or a glued gap reshaped the cell. And
the lattice is nominal (35, 40, 45, 50 …) while the occupied stations are not (90.0 37, 90.0 53,
80.0 51, 83.3 39.4 …), which is why an inshore cell held several real stations.

### Each position against `+proj=calcofi`

## The shipped grid: Voronoi of the official positions {#sec-option-a}

`calcofi4r::cc_grid` is `cc_grid_build(cc_station_positions, cc_grid_v1, cc_grid_land)`
(`calcofi4r/data-raw/cc_grid.R`, no hand edits). The rules, as the function documents them:

1. **Extent.** The outer hull of the previous grid (the union of its cells with interior holes
   filled) minus land. Water that land cuts off from every generator is not part of the grid.
2. **Generators.** The `r nrow(st)` official positions, plus a **seed** for each previous cell
   whose labelled (line, station) lies more than 20 nautical miles outside the convex hull of
   the official stations, so the extended historical grid keeps its cells and keys. A seed is
   the cell's label under `+proj=calcofi`, on land or not, so the edge it shares with its
   neighbours stays where the previous lattice put it. A previous cell inside the 20 nautical
   mile zone that is not a station is retired: its water goes to the nearest generator.
3. **Cells.** The Voronoi tessellation in metres (California Albers, not line/station units,
   which weigh a line unit of 22.2 km and a station unit of 7.4 km alike), clipped to the extent,
   with a vertex every 5 km along each edge so the lon/lat polygon follows the metric edge.
4. **Pockets.** A piece of a cell that land separates from the piece holding its station joins
   the neighbouring cell it shares the longest water edge with. A cell is then one polygon.
5. **Sites.** A cell's site (`grid.geom_ctr`) is its generator; for a seed on land, the previous
   cell's centre when the new cell holds it, else a point on the cell.
6. **Attributes.** A station's cell is `nearshore` at station ≤ 60 and `offshore` beyond;
   `standard` on lines ≥ 76.7 (the 75-station pattern) and `extended` north of it; spacing class 5
   nearshore, 10 offshore. A kept cell keeps the previous cell's attributes and key.

The land is `calcofi4r::cc_grid_land`: OpenStreetMap land polygons
(extract `r cc_grid_land$version`) with islets under 1 km² dropped, the coastline pulled back
300 m and simplified to 100 m, so a ship at its berth or a nearshore position rounded to the
minute still falls in a cell and the cells stay light enough for a browser.

**How offshore cells are bounded.** An official station on the edge of the pattern (station 100
to 120) is bounded seaward by the next historical seed, i.e. the 20-unit lattice, and finally by
the previous outer hull, so an outer official cell reaches about halfway to the historical
lattice beyond it.

not an exact partition in longitude/latitude. The gate in the release is

### Gate 4: R and DuckDB assign the same key {#sec-gate4}

## The climatology and the stations a cell holds {#sec-climatology}

The climatology (`build_climatology()`, calcofi4db ≥ 4.8.0) is keyed on the **station**
(`sample.site_key`), not the cell, so no grid changes a climatology mean; `grid_key` rides on
each row only as the station's modal cell. Two measures, on the climatology's own inputs
(`calcofi_bottle`, `calcofi_ctd-cast`, `calcofi_dic` samples with a `site_key`,
`r CLIM_YR[1]`–`r CLIM_YR[2]`):

- **cells × month with ≥ 3 cruises**, the grain a cell-keyed baseline (or a map consumer) has;
- **climatology rows whose `grid_key` label would change**: the station's modal cell under each
  grid, joined to the release's `climatology` rows.

```{r}
#| label: tbl-climatology
#| tbl-cap: "Effect on the climatology grain: cell × calendar month with at least 3 distinct cruises (1993–2013, climatology input datasets), and climatology rows whose modal-cell label would change."
clim_in <- "dataset_key IN ('calcofi_bottle', 'calcofi_ctd-cast', 'calcofi_dic') AND site_key IS NOT NULL
            AND year(datetime) BETWEEN {CLIM_YR[1]} AND {CLIM_YR[2]}"
cells_month <- function(k) dbGetQuery(con, glue("
  SELECT count(*) n FROM (
    SELECT {k}, month(datetime) m FROM s_key WHERE {k} IS NOT NULL AND {glue(clim_in)}
    GROUP BY ALL HAVING count(DISTINCT cruise_key) >= 3)"))$n
modal <- function(k) glue("
  SELECT dataset_key, site_key, mode({k}) AS cell FROM s_key WHERE {glue(clim_in)} GROUP BY ALL")
clim_change <- function(k) dbGetQuery(con, glue("
  WITH now AS ({modal('key_now')}), opt AS ({modal(k)})
  SELECT count(*) AS n_rows, count(*) FILTER (WHERE now.cell IS DISTINCT FROM opt.cell) AS changed,
         count(DISTINCT (c.dataset_key, c.site_key)) FILTER (WHERE now.cell IS DISTINCT FROM opt.cell) AS stations
  FROM climatology c JOIN now USING (dataset_key, site_key) JOIN opt USING (dataset_key, site_key)"))
# the release's own label against the recomputed modal (they differ only where obs weighting differs)
lab <- dbGetQuery(con, glue("
  WITH now AS ({modal('key_now')})
  SELECT count(*) n, count(*) FILTER (WHERE c.grid_key IS NOT DISTINCT FROM now.cell) same
  FROM climatology c JOIN now USING (dataset_key, site_key)"))
ca <- clim_change("key_a"); cv <- clim_change("key_v"); cb <- clim_change("key_b")
clim_tbl <- tibble(
  grid = c("previous", "shipped", "no SCCOOS", "B", "C"),
  `cells × month with ≥ 3 cruises` = c(cells_month("key_now"), cells_month("key_a"), cells_month("key_v"), cells_month("key_b"), cells_month("key_now")),
  `climatology rows relabelled` = c("", glue("{fmt(ca$changed)} of {fmt(ca$n_rows)} ({ca$stations} stations)"),
                                    glue("{fmt(cv$changed)} of {fmt(cv$n_rows)} ({cv$stations} stations)"),
                                    glue("{fmt(cb$changed)} of {fmt(cb$n_rows)} ({cb$stations} stations)"), "0"))
knitr::kable(clim_tbl)
```

The recomputed modal cell matches the released `climatology.grid_key` on
`r fmt(lab$same)` of `r fmt(lab$n)` rows (the release takes the mode over `obs` rows, this over
samples).

## What shipped, and what is still a question {#sec-recommendation}

**Shipped** (Ben, 2026-10-04): the Voronoi of the 113 official positions, SCCOOS stations
included, with a key crosswalk. It is the only option that fixes both defects at the source:
every official site *is* an official position, which `+proj=calcofi` reproduces to within
`r round(max(st$dist_m))` m; no cell is a remnant of an idealized lattice, so every cell is one
polygon; and no cell holds two official stations (the previous grid: `r hl$previous[5]` cells),
which ends the station mixing that #86 and the climatology work routed around with `site_key`.
Option B removes the slivers but keeps the nominal lattice (`r hl$B[3]` sites still more than
`r OFF_KM` km off their line, `r hl$B[5]` cells still holding several official stations); Option
C moves the dots and nothing else, and cannot place `r sum(!c_ok)` sites at all because their own
line misses their cell.

The price is `r hl$shipped[8]` of `sample` rows changing `grid_key`, `r hl$shipped[9]` moving to
a different cell rather than a renamed one (@tbl-per-dataset), and `r fmt(ca$changed)` of
`r fmt(ca$n_rows)` climatology rows (`r ca$stations` stations) taking a new modal-cell label;
the climatology means do not move (they are keyed on `site_key`), and the cell-month grain with
three or more cruises grows from `r clim_tbl[[2]][1]` to `r clim_tbl[[2]][2]` because the inshore
stations stop sharing cells.

**Choices the build makes that the 2026-10-08 meeting has not seen** (each is one argument or one
rule of `cc_grid_build()` / `cc_grid_land_prep()`, and can change without touching anything else):

1. **Keys.** A cell is named for its station, `st{station}-ln{line}`, decimals as listed
   (`st26.7-ln93.3`, `st26.4-ln93.4`, `st43.5-ln81.7`); a kept cell keeps its previous key.
2. **SCCOOS stations get cells** (@tbl-option-a-cells: `r fmt(min(A$area_km2[which(A$sta_type == "SCCOOS")]), 1)`
   to `r fmt(max(A$area_km2[which(A$sta_type == "SCCOOS")]))` km²), six of the nine on lines of their
   own (81.7, 85.4, 86.8, 88.5, 91.7, 93.4; the rosette station 81.8 46.9 is alone on its line
   too), so a section along line 93.3 no longer includes 93.4 26.4. The variant (@sec-variant) is
   the alternative.
3. **Attributes.** `shore`: nearshore at station ≤ 60. `pattern`: standard on lines ≥ 76.7,
   extended north of it, historical for a kept cell (one kept cell, `st45-ln60`, stays
   `extended`). `spacing`: the nominal class 5 / 10 / 20, not the measured distance to the next
   station. `zone` = `{shore}-{pattern}`.
4. **A historical cast** keys to the nearest official station's cell within 20 nautical miles of
   the official pattern (90.0 32, 1959–84, keys to
   `r cc_grid_key(cc_calcofi_to_lonlat(90, 32)$longitude, cc_calcofi_to_lonlat(90, 32)$latitude)`),
   and to its historical cell beyond. @tbl-a-multi lists the stations this affects since 2004.
5. **Seeds on land.** A kept cell is generated from its label even where the label is on land,
   so its edges stay on the previous lattice; its site is then the previous cell's centre
   (`r rp_$seeds_at_centre` cells) or a point on the cell (`r rp_$seeds_at_water`), not on its line.
6. **The coastline** is OpenStreetMap's, islets under 1 km² dropped, pulled back 300 m and
   simplified to 100 m; cells therefore reach up to 300 m onto land, and `area_km2` includes that
   strip.
7. **Pockets** join the neighbour with the longest shared water edge (@tbl-pockets); water
   touching no cell is left out.
8. **Offshore bound.** An outer official cell reaches halfway to the next historical seed, not a
   fixed distance: 40 nautical miles south of line 93.3, which puts historical line 96.7 on the
   edge (@tbl-line967).

**Still open:** the offshore bound and line 96.7 (@tbl-line967), which is the one result here
that argues with the rule as it was stated; which 9 stations of line 66.7 are the 113-only
infill (the page does not say; all 11 have a cell); whether `st45-ln60` (San Francisco Bay and
its approaches) should exist; and whether the Navy stations need anything on a map.
