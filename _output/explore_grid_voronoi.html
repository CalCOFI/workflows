1 Why, and where this stands

Ben, 2026-10-02 (CalCOFI/workflows#130): a grid point, i.e. a site (x: station, y: line), must land on its line, and the grid has slivers (the calcofi4r “CalCOFI grid” figure; related #86 and CalCOFI/db-viz-station#19). Rather than patch, start from the official station positions and build the cells as a Voronoi tessellation of them.

The first version of this page (2026-10-02) compared that idea (Option A) with two repairs of the previous grid. On 2026-10-04 Ben decided that Option A ships in the next database release, and, the same day, that “kept from the previous grid” is literal: the previous cells beyond the official pattern keep their own boundaries, and the station cells are confined to the previous cells they replace (Section 5). The cells are now built by calcofi4r::cc_grid_build() and bundled as calcofi4r::cc_grid; calcofi4db::assign_grid_key() keys a position to a cell, and the release publishes a grid_crosswalk table. This page is the evidence pack for that implementation: the six gates an independent review set (Section 9), each measured here on the promoted release v2026.10.01, and the same headline numbers for one variant (no SCCOOS inshore cells) to put beside it at the 2026-10-08 meeting.

This is an exploration, not an ingest. It has no calcofi: block, like every other explore_*.qmd, so build_targets_list() never sees it: it is not a target, not a release input, and it writes nothing to cc_stage_dir(). It changes no grid_key. It reads the published release v2026.10.01 (the local copy under cc_stage_dir()/releases/ when there is one) and writes only this page.

# polygon parts of a keyed sf, with area (km²) and mean width 2A/P (km)
split_parts <- function(x, key = "grid_key") {
  p <- x |> select(all_of(key)) |> st_cast("MULTIPOLYGON") |> st_cast("POLYGON", warn = FALSE)
  p$area_km2 <- as.numeric(st_area(p)) / 1e6
  p$width_km <- 2 * p$area_km2 / (as.numeric(st_length(st_cast(st_geometry(p), "MULTILINESTRING"))) / 1000)
  p |> group_by(across(all_of(key))) |>
    mutate(part = row_number(), n_parts = n(), largest = area_km2 == max(area_km2)) |> ungroup()
}
# a part is a sliver when it does not hold its cell's generator (the station it is the cell of)
# and it is thin or small
flag_slivers <- function(parts, gen, key = "grid_key") {
  hit <- mapply(function(p, k) {
    gi <- which(gen[[key]] == k); length(gi) && st_intersects(p, st_geometry(gen)[gi], sparse = FALSE)[1, 1]
  }, st_geometry(parts), parts[[key]])
  parts$holds_gen <- hit
  parts$sliver    <- !hit & (parts$width_km < SLIVER_W | parts$area_km2 < SLIVER_A)
  # a sliver touching another cell is the visible defect; one touching none is a pocket of
  # water the land mask cuts off (a lagoon, a harbour)
  nb <- st_is_within_distance(parts, parts, 50)
  parts$touches_other <- mapply(function(i, k) any(parts[[key]][i] != k), nb, parts[[key]])
  parts
}
# absorb every sliver into the neighbouring cell it shares the longest edge with,
# smallest first; a sliver with no neighbour keeps its key (reported)
absorb_slivers <- function(parts, key = "grid_key", tol_m = 50) {
  parts$key_new  <- parts[[key]]
  parts$shared_m <- NA_real_
  for (pid in order(parts$area_km2)) {
    if (!parts$sliver[pid]) next
    me     <- parts[pid, ]
    others <- which(parts$key_new != me$key_new)
    cand   <- others[st_intersects(st_buffer(st_geometry(me), tol_m), st_geometry(parts)[others], sparse = FALSE)[1, ]]
    if (!length(cand)) next
    bnd <- st_boundary(st_geometry(me))
    len <- vapply(cand, function(j) {
      x <- st_intersection(bnd, st_buffer(st_geometry(parts)[j], tol_m))
      if (!length(x) || all(st_is_empty(x))) 0 else sum(as.numeric(st_length(x)))
    }, numeric(1))
    if (max(len) <= 0) next
    parts$key_new[pid]  <- parts$key_new[cand[which.max(len)]]
    parts$shared_m[pid] <- max(len)
  }
  parts
}

}

2 How the previous grid was built

The release’s grid table through v2026.10.01 (218 cells) is calcofi4r::cc_grid as it was through calcofi4r 1.24.2, kept now as calcofi4r::cc_grid_v1, with each cell named st{station}-ln{line} (_hist for the historical pattern). Every ingest calls calcofi4db::assign_grid_key(), a point-in-polygon test of the sample’s position against those cells, so grid_key on sample and obs is wherever the position falls.

That grid came from calcofi4r/data-raw/cc_grid_v1.R, which:

  1. lays three idealized lattices in +proj=calcofi (line, station) coordinates, not the occupied positions: 5-unit spacing for stations ≤ 60 on the standard lines, 10-unit spacing offshore to station 120, and a 20-unit historical lattice out to the convex hull of every CTD cast;
  2. takes a Voronoi tessellation of each lattice (in line/station units), cuts the finer ones out of the coarser, and hand-merges six historical pairs (e.g. 55/80 from 50/80 + 60/80);
  3. keeps the cells listed in data-raw/cc_grid_sta-keys.csv and erases Natural Earth 10 m land (st_difference), which leaves gaps along the coast;
  4. glues five of those gaps back onto line 93.3 cells by hand (cc_grid_box4slivers.geojson, st_union onto 93.3,30 … 93.3,110), which is where the line-93.3 cells pick up second, detached parts;
  5. makes the site of each cell st_centroid(geom, of_largest_polygon = TRUE) on lon/lat (cc_grid_ctrs; the release’s grid.geom_ctr).

So a site was the centroid of whatever polygon survived steps 2–4, never a station position: that is why sites left their line wherever land, a merge or a glued gap reshaped the cell. And the lattice is nominal (35, 40, 45, 50 …) while the occupied stations are not (90.0 37, 90.0 53, 80.0 51, 83.3 39.4 …), which is why an inshore cell held several real stations.

5 The shipped grid: one cell per official station, inside the previous grid

calcofi4r::cc_grid is cc_grid_build(cc_station_positions, cc_grid_v1, cc_grid_land) (calcofi4r/data-raw/cc_grid.R, no hand edits). The rules, as the function documents them:

  1. Extent. The outer hull of the previous grid (the union of its cells with interior holes filled) minus land.
  2. Kept or replaced. A previous cell whose labelled (line, station) lies more than 20 nautical miles outside the convex hull of the 113 official stations is kept; the others are replaced. Where two previous cells overlap, the overlap is the cell whose key sorts first, the cell a position there keyed to.
  3. Kept cells are the previous cells. A kept cell keeps its key, its attributes and its own boundaries, toward the other kept cells and toward the replaced region, so a historical position that was in a kept cell is still in it. Only its coast side changes: it ends at the new land.
  4. Station cells. The Voronoi tessellation of the official positions in metres (California Albers, not line/station units, which weigh a line unit of 22.2 km and a station unit of 7.4 km alike), confined to the replaced region R (the union of the replaced cells): an outer station’s cell stops where the previous lattice stopped it, at line 95.0 in the south (20 nautical miles beyond line 93.3). Each edge gets a vertex every 5 km so the lon/lat polygon follows the metric edge.
  5. Pockets. A piece of a station’s cell that land separates from the piece holding the station joins the neighbouring station cell it shares the longest water edge with. A pocket never joins a kept cell. Water of R that no station cell reaches stays with the station it is nearest to, as a detached part, and is reported (Table 11).
  6. Gap water. Water of the extent that no previous cell covered (the previous grid was clipped by a coarser coastline) joins the cell whose edge it is nearest to, kept or replaced. Gap water that touches no cell is left out.
  7. Sites. A station cell’s site (grid.geom_ctr) is the station. A kept cell’s site is its label under +proj=calcofi when the cell holds it, else the previous cell’s centre, else a point on the cell.
  8. Attributes. A station’s cell is nearshore at station ≤ 60 and offshore beyond; standard on lines ≥ 76.7 (the 75-station pattern) and extended north of it; spacing class 5 nearshore, 10 offshore. A kept cell keeps the previous cell’s attributes.

The land is calcofi4r::cc_grid_land: OpenStreetMap land polygons (extract 2026-08-31) with islets under 1 km² dropped, the coastline pulled back 300 m and simplified to 100 m, so a ship at its berth or a nearshore position rounded to the minute still falls in a cell and the cells stay light enough for a browser.

Why the station cells are confined. A first build let the official Voronoi run to the bisector with the kept cells’ labels. The outer official cells then reached 40 nautical miles beyond line 93.3 (halfway to the line-100 lattice), where the previous lattice gave them 20, and historical line 96.7 fell on the new edge: 18,795 of its 28,367 sample rows left the line-100 cells and seven of its stations were split between two cells. Confining the station cells to R puts every boundary of the previous grid that was not inside the official pattern back where it was (Table 20, Table 9).

12 What shipped, and what is still a question

Shipped (Ben, 2026-10-04): one cell per official station, SCCOOS stations included, as the Voronoi of the 113 official positions confined to the previous cells it replaces; the previous cells beyond the official pattern kept as they were; and a key crosswalk. It is the only option that fixes both defects at the source: every official site is an official position, which +proj=calcofi reproduces to within 18 m; no station cell is a remnant of an idealized lattice; and no cell holds two official stations (the previous grid: 13 cells), which ends the station mixing that #86 and the climatology work routed around with site_key. Option B removes the slivers but keeps the nominal lattice (42 sites still more than 1 km off their line, 12 cells still holding several official stations); Option C moves the dots and nothing else, and cannot place 7 sites at all because their own line misses their cell.

The price is 12.7% of sample rows changing grid_key, 5.4% moving to a different cell rather than a renamed one (Table 17), all of them inside the official pattern, and 86,711 of 777,501 climatology rows (44 stations) taking a new modal-cell label; the climatology means do not move (they are keyed on site_key), and the cell-month grain with three or more cruises grows from 513 to 602 because the inshore stations stop sharing cells.

  3. Attributes. shore: nearshore at station ≤ 60. pattern: standard on lines ≥ 76.7, extended north of it, historical for a kept cell (one kept cell, st45-ln60, stays extended). spacing: the nominal class 5 / 10 / 20, not the measured distance to the next station. zone = {shore}-{pattern}.
  4. Kept cells are the previous cells (Ben, 2026-10-04): the 112 previous cells whose label is more than 20 nautical miles outside the official pattern keep their own boundaries and their pieces (13 are in several). No sample row leaves one (Table 9).

## Why, and where this stands {#sec-why}

Ben, 2026-10-02 ([CalCOFI/workflows#130](https://github.com/CalCOFI/workflows/issues/130)):
a grid point, i.e. a **site** (x: station, y: line), must land on its line, and the grid has
**slivers** (the [calcofi4r "CalCOFI grid"
figure](https://calcofi.io/calcofi4r/articles/calcofi4r.html#calcofi-grid); related
[#86](https://github.com/CalCOFI/workflows/issues/86) and
[CalCOFI/db-viz-station#19](https://github.com/CalCOFI/db-viz-station/issues/19)). Rather than
patch, start from the [official station
positions](https://calcofi.org/sampling-info/station-positions/) and build the cells as a Voronoi
tessellation of them.

The first version of this page (2026-10-02) compared that idea (Option A) with two repairs of the
previous grid. **On 2026-10-04 Ben decided that Option A ships in the next database release**,
and, the same day, that "kept from the previous grid" is literal: the previous cells beyond the
official pattern keep their own boundaries, and the station cells are confined to the previous
cells they replace (@sec-option-a).
The cells are now built by `calcofi4r::cc_grid_build()` and bundled as `calcofi4r::cc_grid`;
`calcofi4db::assign_grid_key()` keys a position to a cell, and the release publishes a
`grid_crosswalk` table. This page is the **evidence pack** for that implementation: the six
gates an independent review set (@sec-gates), each measured here on the promoted release
v2026.10.01, and the same headline numbers for one variant (no SCCOOS inshore cells) to put
beside it at the 2026-10-08 meeting.

This is an **exploration**, not an ingest. It has no `calcofi:` block, like every other
`explore_*.qmd`, so `build_targets_list()` never sees it: it is not a target, not a release
input, and it writes nothing to `cc_stage_dir()`. It changes no `grid_key`. It reads the published
release v2026.10.01 (the local copy under `cc_stage_dir()/releases/` when there is one) and writes
only this page.

# helpers ----
# polygon parts of a keyed sf, with area (km²) and mean width 2A/P (km)
split_parts <- function(x, key = "grid_key") {
  p <- x |> select(all_of(key)) |> st_cast("MULTIPOLYGON") |> st_cast("POLYGON", warn = FALSE)
  p$area_km2 <- as.numeric(st_area(p)) / 1e6
  p$width_km <- 2 * p$area_km2 / (as.numeric(st_length(st_cast(st_geometry(p), "MULTILINESTRING"))) / 1000)
  p |> group_by(across(all_of(key))) |>
    mutate(part = row_number(), n_parts = n(), largest = area_km2 == max(area_km2)) |> ungroup()
}
# a part is a sliver when it does not hold its cell's generator (the station it is the cell of)
# and it is thin or small
flag_slivers <- function(parts, gen, key = "grid_key") {
  hit <- mapply(function(p, k) {
    gi <- which(gen[[key]] == k); length(gi) && st_intersects(p, st_geometry(gen)[gi], sparse = FALSE)[1, 1]
  }, st_geometry(parts), parts[[key]])
  parts$holds_gen <- hit
  parts$sliver    <- !hit & (parts$width_km < SLIVER_W | parts$area_km2 < SLIVER_A)
  # a sliver touching another cell is the visible defect; one touching none is a pocket of
  # water the land mask cuts off (a lagoon, a harbour)
  nb <- st_is_within_distance(parts, parts, 50)
  parts$touches_other <- mapply(function(i, k) any(parts[[key]][i] != k), nb, parts[[key]])
  parts
}
# absorb every sliver into the neighbouring cell it shares the longest edge with,
# smallest first; a sliver with no neighbour keeps its key (reported)
absorb_slivers <- function(parts, key = "grid_key", tol_m = 50) {
  parts$key_new  <- parts[[key]]
  parts$shared_m <- NA_real_
  for (pid in order(parts$area_km2)) {
    if (!parts$sliver[pid]) next
    me     <- parts[pid, ]
    others <- which(parts$key_new != me$key_new)
    cand   <- others[st_intersects(st_buffer(st_geometry(me), tol_m), st_geometry(parts)[others], sparse = FALSE)[1, ]]
    if (!length(cand)) next
    bnd <- st_boundary(st_geometry(me))
    len <- vapply(cand, function(j) {
      x <- st_intersection(bnd, st_buffer(st_geometry(parts)[j], tol_m))
      if (!length(x) || all(st_is_empty(x))) 0 else sum(as.numeric(st_length(x)))
    }, numeric(1))
    if (max(len) <= 0) next
    parts$key_new[pid]  <- parts$key_new[cand[which.max(len)]]
    parts$shared_m[pid] <- max(len)
  }
  parts
}
# the cell a point falls in, in metres (the key that sorts first on a tie, as cc_grid_key())
first_hit <- function(pts, cells, key = "grid_key") {
  ix <- st_intersects(pts, cells)
  vapply(ix, function(i) if (length(i)) sort(cells[[key]][i], method = "radix")[1] else NA_character_, "")
}
# a site's distance from its line, km (+proj=calcofi via calcofi4db, never re-implemented)
off_line_km <- function(lon, lat, line) {
  p <- cc_lonlat_to_calcofi(lon, lat)
  abs(p$line - line) * KM_LINE
}
n_vertices <- function(x) sum(vapply(st_geometry(x), function(g) nrow(st_coordinates(g)), 1))
fmt <- function(x, d = 0) format(round(x, d), big.mark = ",", nsmall = d, trim = TRUE)
pct <- function(x, d = 1) paste0(format(round(100 * x, d), nsmall = d, trim = TRUE), "%")

## How the previous grid was built {#sec-today-build}

The release's `grid` table through v2026.10.01 (218 cells) is `calcofi4r::cc_grid` as it was
through calcofi4r 1.24.2, kept now as `calcofi4r::cc_grid_v1`, with each cell named
`st{station}-ln{line}` (`_hist` for the historical pattern). Every ingest calls
`calcofi4db::assign_grid_key()`, a point-in-polygon test of the sample's position against those
cells, so `grid_key` on `sample` and `obs` is wherever the position falls.

That grid came from `calcofi4r/data-raw/cc_grid_v1.R`, which:

1. lays three **idealized lattices** in `+proj=calcofi` (line, station) coordinates, not the
   occupied positions: 5-unit spacing for stations ≤ 60 on the standard lines, 10-unit spacing
   offshore to station 120, and a 20-unit historical lattice out to the convex hull of every
   CTD cast;
2. takes a Voronoi tessellation of each lattice (in line/station units), cuts the finer ones
   out of the coarser, and hand-merges six historical pairs (e.g. 55/80 from 50/80 + 60/80);
3. keeps the cells listed in `data-raw/cc_grid_sta-keys.csv` and erases Natural Earth 10 m land
   (`st_difference`), which leaves gaps along the coast;
4. glues five of those gaps back onto line 93.3 cells by hand (`cc_grid_box4slivers.geojson`,
   `st_union` onto `93.3,30` … `93.3,110`), which is where the line-93.3 cells pick up second,
   detached parts;
5. makes the site of each cell `st_centroid(geom, of_largest_polygon = TRUE)` on lon/lat
   (`cc_grid_ctrs`; the release's `grid.geom_ctr`).

So a site was the centroid of whatever polygon survived steps 2–4, never a station position:
that is why sites left their line wherever land, a merge or a glued gap reshaped the cell. And
the lattice is nominal (35, 40, 45, 50 …) while the occupied stations are not (90.0 37, 90.0 53,
80.0 51, 83.3 39.4 …), which is why an inshore cell held several real stations.

`libs/download_station_positions.R` fetches the page and its linked files and stops if the
page's table, the linked `CalCOFIStationOrder.csv` and `CalCOFI_113StationMap.kml` disagree; its
tidy output (fetched 2026-10-02) is bundled as `calcofi4r::cc_station_positions`, which is what
the grid is built from. It is checked here against the copy of the linked CSV this repo tracks
(`data/station-positions/CalCOFIStationOrder.csv`).

What the page lists:

- **Station Position (Lat/Lon), Depth, and Type**: `r nrow(st)` stations, `r n_ros` typed ROS
  and `r n_sccoos` SCCOOS, on `r n_distinct(st$line)` lines (60 to 93.4), with order occupied
  and estimated depth. This is the **113-station pattern**.
- The **75-station pattern** (standard since 1984; summer and fall): "66 stations from San Diego
  to Avila Beach" on the 6 lines 93.3 to 76.7, plus "9 additional coastal ~20 m SCCOOS stations".
  In the table that is every row with line ≥ 76.7: `r sum(st$in_75)` rows.
- The **104-station pattern** (winter and spring) adds 29 stations on lines 73.3 to 60.0; the 113
  pattern adds 9 more by sampling every 20 nm on line 66.7. The page does not say which 9, so
  the 104 subset is not marked.
- **Navy Stations**: `r sum(!is.na(st$navy_ops_area))` standard-pattern stations Navy operations
  may close, with the operations area.
- Not listed: any historical station (e.g. 90.0 32, occupied 1959–84), any line north of 60 or
  south of 93.4, or the Baja and Gulf of California lines.

### Each position against `+proj=calcofi`

`calcofi4db::cc_lonlat_to_calcofi()` projects each official lon/lat to continuous (line,
station); the residual is that minus the station's label, and the distance is from the official
position to `cc_calcofi_to_lonlat()` of the label.

```{r}
#| label: tbl-residuals

st <- st |> mutate(
  d_line = pr$line - line, d_sta = pr$station - station,
  dist_m = as.numeric(st_distance(
    st_as_sf(st, coords = c("longitude", "latitude"), crs = 4326),
    st_as_sf(nm, coords = c("longitude", "latitude"), crs = 4326), by_element = TRUE)))

u <- cc_calcofi_to_lonlat(c(90, 91, 90), c(60, 60, 61))
suppressMessages(sf_use_s2(TRUE))
km_unit <- as.numeric(st_distance(st_as_sf(u, coords = c("longitude", "latitude"), crs = 4326))[1, 2:3]) / 1000
suppressMessages(sf_use_s2(FALSE))
stopifnot(abs(km_unit[1] - KM_LINE) < 0.01, abs(km_unit[2] - KM_STA) < 0.01)
st |> group_by(sta_type) |>
  summarize(
    n = n(),
    `max |Δ line|` = signif(max(abs(d_line)), 2), `max |Δ station|` = signif(max(abs(d_sta)), 2),
    `median distance (m)` = round(median(dist_m), 1), `max distance (m)` = round(max(dist_m), 1)) |>

```

Every official position is its label under `+proj=calcofi` to within
**`r round(max(st$dist_m))` m** (`r signif(max(abs(st$d_sta)), 2)` station units at most): the
table is the projection, rounded. One line unit is `r round(km_unit[1], 2)` km and one station
unit `r round(km_unit[2], 3)` km (4 nmi). So an official position *is* on its line, and a
Voronoi built from them inherits that.

The sub-kilometre offsets are built into the lattice: the lines are 3.3 and 3.4 units apart in
turn (80, 83.3, 86.7, 90 …), and a Voronoi edge sits at the midpoint, so the centre of every cell
on lines 76.7, 83.3, 86.7 and 93.3 is 0.025 line units (about 0.55 km) off its line, while lines
80 and 90 sit almost on it (the median offset of a site on a 10-unit cell is
`r fmt(median(grid$off_km[grid$spacing == 10 & grid$line %in% c(76.7, 83.3, 86.7, 93.3)]), 2)` km
on those four lines and
`r fmt(median(grid$off_km[grid$spacing == 10 & grid$line %in% c(80, 90)]), 2)` km on 80 and 90).
The large offsets are the cells that land, a hand-merge or a glued gap reshaped (@tbl-offline).

## The shipped grid: one cell per official station, inside the previous grid {#sec-option-a}

`calcofi4r::cc_grid` is `cc_grid_build(cc_station_positions, cc_grid_v1, cc_grid_land)`
(`calcofi4r/data-raw/cc_grid.R`, no hand edits). The rules, as the function documents them:

1. **Extent.** The outer hull of the previous grid (the union of its cells with interior holes
   filled) minus land.
2. **Kept or replaced.** A previous cell whose labelled (line, station) lies more than 20
   nautical miles outside the convex hull of the `r nrow(st)` official stations is **kept**; the
   others are **replaced**. Where two previous cells overlap, the overlap is the cell whose key
   sorts first, the cell a position there keyed to.
3. **Kept cells are the previous cells.** A kept cell keeps its key, its attributes and its own
   boundaries, toward the other kept cells and toward the replaced region, so a historical
   position that was in a kept cell is still in it. Only its coast side changes: it ends at the
   new land.
4. **Station cells.** The Voronoi tessellation of the official positions in metres (California
   Albers, not line/station units, which weigh a line unit of 22.2 km and a station unit of 7.4 km
   alike), **confined to the replaced region R** (the union of the replaced cells): an outer
   station's cell stops where the previous lattice stopped it, at line 95.0 in the south (20
   nautical miles beyond line 93.3). Each edge gets a vertex every 5 km so the lon/lat polygon
   follows the metric edge.
5. **Pockets.** A piece of a station's cell that land separates from the piece holding the
   station joins the neighbouring station cell it shares the longest water edge with. A pocket
   never joins a kept cell. Water of R that no station cell reaches stays with the station it is
   nearest to, as a detached part, and is reported (@tbl-cases).
6. **Gap water.** Water of the extent that no previous cell covered (the previous grid was
   clipped by a coarser coastline) joins the cell whose edge it is nearest to, kept or replaced.
   Gap water that touches no cell is left out.
7. **Sites.** A station cell's site (`grid.geom_ctr`) is the station. A kept cell's site is its
   label under `+proj=calcofi` when the cell holds it, else the previous cell's centre, else a
   point on the cell.
8. **Attributes.** A station's cell is `nearshore` at station ≤ 60 and `offshore` beyond;
   `standard` on lines ≥ 76.7 (the 75-station pattern) and `extended` north of it; spacing class 5
   nearshore, 10 offshore. A kept cell keeps the previous cell's attributes.

The land is `calcofi4r::cc_grid_land`: OpenStreetMap land polygons
(extract `r cc_grid_land$version`) with islets under 1 km² dropped, the coastline pulled back
300 m and simplified to 100 m, so a ship at its berth or a nearshore position rounded to the
minute still falls in a cell and the cells stay light enough for a browser.

**Why the station cells are confined.** A first build let the official Voronoi run to the
bisector with the kept cells' labels. The outer official cells then reached 40 nautical miles
beyond line 93.3 (halfway to the line-100 lattice), where the previous lattice gave them 20, and
historical line 96.7 fell on the new edge: 18,795 of its 28,367 `sample` rows left the line-100
cells and seven of its stations were split between two cells. Confining the station cells to R
puts every boundary of the previous grid that was not inside the official pattern back where it
was (@tbl-line967, @tbl-kept).

## The six gates {#sec-gates}

An independent review of the 2026-10-02 notebook set six conditions for shipping. Each is
measured below on the shipped cells and v2026.10.01; @tbl-gates is the summary.

The gate is zero `sample` rows that have a cell under the previous grid and none under the new

### Gate 3: a crosswalk that covers every previous key {#sec-gate3}

84 of the 113 station cells reuse a key whose polygon changed, so nothing may map between the
grids by name. `calcofi4db::build_grid_crosswalk()` writes the release table `grid_crosswalk`:
one row per overlapping pair of a previous and a shipped cell, with the overlap area and its
share of each (`prev_frac`, `grid_frac`), areas in California Albers. Shares are of the whole
cell and are never rescaled, so a previous cell's shares sum to one less the part of it that is
land under the finer coastline.

### Gate 4: R and DuckDB assign the same key {#sec-gate4}

The cells are built in metres and tested in longitude/latitude. The published polygon is the
definition: a vertex every 5 km along each Voronoi edge keeps the lon/lat chord within a metre
of the metric edge, a kept cell's edges are the previous cell's own lon/lat edges, the same
vertices are shared by the cells on both sides, and both engines
apply one rule (planar intersects; on a shared edge the key that sorts first in byte order:
`calcofi4r::cc_grid_key()` in R, `min(grid_key)` in `calcofi4db::assign_grid_key()`). Until now
the DuckDB rule was `LIMIT 1` with no order.

**DIC is an ingest gap, not positions outside the grid.** Every DIC row has a position and every

parent cast (the `key_null_iff_no_parent` column). The ingest has since been changed (2026-10-04,

own position, keeping a matched cast's key where there is one. That last clause meets the new
release gate: `check_grid_key_assignment()` stops on a row whose key is not the cell its own
position is in, and a cast-matched DIC sample taken a little off its cast's position can carry
the cast's cell (1 of the 6 in the previous grid). Either the ingest keys every sample by its own
position, or the gate is told which rows inherit a key. `calcofi_phytoplankton` is region-pooled:

## What shipped, and what is still a question {#sec-recommendation}

**Shipped** (Ben, 2026-10-04): one cell per official station, SCCOOS stations included, as the
Voronoi of the 113 official positions confined to the previous cells it replaces; the previous
cells beyond the official pattern kept as they were; and a key crosswalk. It is the only option
that fixes both defects at the source: every official site *is* an official position, which
`+proj=calcofi` reproduces to within `r round(max(st$dist_m))` m; no station cell is a remnant
of an idealized lattice; and no cell holds two official stations (the previous grid:
`r hl$previous[5]` cells), which ends the station mixing that #86 and the climatology work routed
around with `site_key`. Option B removes the slivers but keeps the nominal lattice
(`r hl$B[3]` sites still more than `r OFF_KM` km off their line, `r hl$B[5]` cells still holding
several official stations); Option C moves the dots and nothing else, and cannot place
`r sum(!c_ok)` sites at all because their own line misses their cell.

The price is `r hl$shipped[9]` of `sample` rows changing `grid_key`, `r hl$shipped[10]` moving to
a different cell rather than a renamed one (@tbl-per-dataset), all of them inside the official
pattern, and `r fmt(ca$changed)` of `r fmt(ca$n_rows)` climatology rows (`r ca$stations`
stations) taking a new modal-cell label; the climatology means do not move (they are keyed on
`site_key`), and the cell-month grain with three or more cruises grows from
`r clim_tbl[[2]][1]` to `r clim_tbl[[2]][2]` because the inshore stations stop sharing cells.

**Choices the build makes that the 2026-10-08 meeting has not seen** (each is one argument or one
rule of `cc_grid_build()` / `cc_grid_land_prep()`, and can change without touching anything else):

1. **Keys.** A cell is named for its station, `st{station}-ln{line}`, decimals as listed
   (`st26.7-ln93.3`, `st26.4-ln93.4`, `st43.5-ln81.7`); a kept cell keeps its previous key.
2. **SCCOOS stations get cells** (@tbl-option-a-cells: `r fmt(min(A$area_km2[which(A$sta_type == "SCCOOS")]), 1)`
   to `r fmt(max(A$area_km2[which(A$sta_type == "SCCOOS")]))` km²), six of the nine on lines of their
   own (81.7, 85.4, 86.8, 88.5, 91.7, 93.4; the rosette station 81.8 46.9 is alone on its line
   too), so a section along line 93.3 no longer includes 93.4 26.4. The variant (@sec-variant) is
   the alternative.
3. **Attributes.** `shore`: nearshore at station ≤ 60. `pattern`: standard on lines ≥ 76.7,
   extended north of it, historical for a kept cell (one kept cell, `st45-ln60`, stays
   `extended`). `spacing`: the nominal class 5 / 10 / 20, not the measured distance to the next
   station. `zone` = `{shore}-{pattern}`.
4. **Kept cells are the previous cells** (Ben, 2026-10-04): the `r length(kept_keys)` previous
   cells whose label is more than 20 nautical miles outside the official pattern keep their own
   boundaries and their pieces (`r n_multi_kept` are in several). No `sample` row leaves one
   (@tbl-kept).
5. **The station cells are confined to the previous cells they replace** (Ben, 2026-10-04), so
   the outer station cells stop where the previous lattice stopped them: line 95.0 in the south,
   and the previous cells' outer edges to the north and offshore. Three replaced cells are
   historical ones just beyond the pattern (`r paste(prevt$grid_key[prevt$fate == "replaced" & prevt$sta_pattern == "historical"], collapse = ", ")`):
   the outer station cells take their water, up to `r fmt(max(A$area_km2[A$gen_source == "official"]))` km².
6. **A historical cast** inside the replaced region keys to the nearest official station's cell
   (90.0 32, 1959–84, keys to
   `r cc_grid_key(cc_calcofi_to_lonlat(90, 32)$longitude, cc_calcofi_to_lonlat(90, 32)$latitude)`),
   and to its kept cell beyond. @tbl-a-multi lists the stations this affects since 2004.
7. **A kept cell's site** is its label, else the previous cell's centre
   (`r sum(prevt$site_at == "centre", na.rm = TRUE)` cells, label on land), else a point on the
   cell (`r sum(prevt$site_at == "water", na.rm = TRUE)`).
8. **The coastline** is OpenStreetMap's, islets under 1 km² dropped, pulled back 300 m and
   simplified to 100 m; cells therefore reach up to 300 m onto land, and `area_km2` includes that
   strip. Water between the previous grid's coarser coastline and this one joins the cell it is
   nearest to (`r fmt(sum(prevt$gap_km2))` km² to the kept cells).
9. **Pockets** join the neighbouring station cell with the longest shared water edge
   (@tbl-pockets), never a kept cell.
10. **Previous cells that overlap** (along the line 93.3 / line 100 boundary, under 1 km² in all):
    the overlap is the cell whose key sorts first, which is the cell `cc_grid_key()` gives a
    position there in the previous grid.
