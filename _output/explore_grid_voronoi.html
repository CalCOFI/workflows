1 Why

Ben, 2026-10-02 (CalCOFI/workflows#130): a grid point, i.e. a site (x: station, y: line), must land on its line, and the grid has slivers (the calcofi4r “CalCOFI grid” figure; related #86 and CalCOFI/db-viz-station#19). Rather than patch, start from the official station positions and build the cells as a Voronoi tessellation of them.

This is an exploration, not an ingest. It has no calcofi: block, like every other explore_*.qmd, so build_targets_list() never sees it: it is not a target, not a release input, and it writes nothing to cc_stage_dir()/parquet. It changes no grid_key. It reads the published release v2026.10.01 and writes only the downloaded station table (under cc_stage_dir()/reference/) and this page.

# polygon parts of a keyed sf, with area (km²) and mean width 2A/P (km)
split_parts <- function(x, key = "grid_key") {
  p <- x |> select(all_of(key)) |> st_cast("MULTIPOLYGON") |> st_cast("POLYGON", warn = FALSE)
  p$area_km2 <- as.numeric(st_area(p)) / 1e6
  p$width_km <- 2 * p$area_km2 / (as.numeric(st_length(st_cast(st_geometry(p), "MULTILINESTRING"))) / 1000)
  p |> group_by(across(all_of(key))) |>
    mutate(part = row_number(), n_parts = n(), largest = area_km2 == max(area_km2)) |> ungroup()
}
# a part is a sliver when it does not hold its cell's generator (the station it is the cell of)
# and it is thin or small
flag_slivers <- function(parts, gen, key = "grid_key") {
  gk  <- gen[[key]][match(parts[[key]], gen[[key]])]
  hit <- mapply(function(p, k) {
    gi <- which(gen[[key]] == k); length(gi) && st_intersects(p, st_geometry(gen)[gi], sparse = FALSE)[1, 1]
  }, st_geometry(parts), parts[[key]])
  parts$holds_gen <- hit
  parts$sliver    <- !hit & (parts$width_km < SLIVER_W | parts$area_km2 < SLIVER_A)
  # a sliver touching another cell is the visible defect; one touching none is a pocket of
  # water the land mask cuts off (a lagoon, a harbour) and stays with its cell
  nb <- st_is_within_distance(parts, parts, 50)
  parts$touches_other <- mapply(function(i, k) any(parts[[key]][i] != k), nb, parts[[key]])
  parts
}
# absorb every sliver into the neighbouring cell it shares the longest edge with,
# smallest first; a sliver with no neighbour keeps its key (reported)
absorb_slivers <- function(parts, key = "grid_key", tol_m = 50) {
  parts$key_new  <- parts[[key]]
  parts$shared_m <- NA_real_
  for (pid in order(parts$area_km2)) {
    if (!parts$sliver[pid]) next
    me     <- parts[pid, ]
    others <- which(parts$key_new != me$key_new)
    cand   <- others[st_intersects(st_buffer(st_geometry(me), tol_m), st_geometry(parts)[others], sparse = FALSE)[1, ]]
    if (!length(cand)) next
    bnd <- st_boundary(st_geometry(me))
    len <- vapply(cand, function(j) {
      x <- st_intersection(bnd, st_buffer(st_geometry(parts)[j], tol_m))
      if (!length(x) || all(st_is_empty(x))) 0 else sum(as.numeric(st_length(x)))
    }, numeric(1))
    if (max(len) <= 0) next
    parts$key_new[pid]  <- parts$key_new[cand[which.max(len)]]
    parts$shared_m[pid] <- max(len)
  }
  parts
}
# the first cell a point falls in (assign_grid_key()'s ST_Intersects ... LIMIT 1)
first_hit <- function(pts, cells, key = "grid_key") {
  ix <- st_intersects(pts, cells)
  vapply(ix, function(i) if (length(i)) cells[[key]][i[1]] else NA_character_, "")
}

off_line_km <- function(lon, lat, line) {
  p <- cc_lonlat_to_calcofi(lon, lat)

}

2 How today’s grid is built

The release’s grid table (218 cells) is calcofi4db::build_grid_reference(), which reads two datasets bundled in calcofi4r, cc_grid (cells) and cc_grid_ctrs (sites), and names each cell st{station}-ln{line} (_hist for the historical pattern). Every ingest then calls calcofi4db::assign_grid_key(), a point-in-polygon ST_Intersects … LIMIT 1 of the sample’s position against those cells, so grid_key on sample and obs is wherever the position falls.

cc_grid comes from calcofi4r/data-raw/cc_grid.R, which:

  1. lays three idealized lattices in +proj=calcofi (line, station) coordinates, not the occupied positions: 5-unit spacing for stations ≤ 60 on the standard lines, 10-unit spacing offshore to station 120, and a 20-unit historical lattice out to the convex hull of every CTD cast;
  2. takes a Voronoi tessellation of each lattice (in line/station units), cuts the finer ones out of the coarser, and hand-merges six historical pairs (e.g. 55/80 from 50/80 + 60/80);
  3. keeps the cells listed in data-raw/cc_grid_sta-keys.csv and erases Natural Earth 10 m land (st_difference), which leaves gaps along the coast;
  4. glues five of those gaps back onto line 93.3 cells by hand (cc_grid_box4slivers.geojson, st_union onto 93.3,30 … 93.3,110), which is where the line-93.3 cells pick up second, detached parts;
  5. makes the site of each cell st_centroid(geom, of_largest_polygon = TRUE) on lon/lat (cc_grid_ctrs; the release’s grid.geom_ctr).

So a site is the centroid of whatever polygon survived steps 2–4, never a station position: that is why sites leave their line wherever land, a merge or a glued gap reshaped the cell. And the lattice is nominal (35, 40, 45, 50 …) while the occupied stations are not (90.0 37, 90.0 53, 80.0 51, 83.3 39.4 …), which is why an inshore cell holds several real stations.

5 Option A: Voronoi of the official positions

The generators are the 113 official positions. Outside the official pattern (beyond the convex hull of the official stations buffered by 20 nm, half the offshore spacing) today’s cells are kept as generators at their labelled (line, station) under +proj=calcofi, so the historical and Baja extent keeps a cell for every sample it holds today; a generator on land is dropped. The Voronoi is taken in metres (California Albers), not in line/station units, which weigh a line unit (22.2 km) and a station unit (7.4 km) alike. It is clipped to today’s outer hull (with interior holes filled) and to the OSM land mask, and then the coastline’s leftovers (pieces cut off by land that hold no station: the same sliver rule) are absorbed into the neighbour they share the longest edge with.

How offshore cells are bounded. An official station on the edge of the pattern (station 100 to 120) is bounded seaward by the next historical generator, i.e. the 20-unit lattice, and finally by today’s outer hull, so an outer official cell reaches about halfway to the historical lattice beyond it. The alternative (a fixed buffer around the official stations, with everything beyond keyed only to the historical cells) is a question below.

10 Recommendation

Option A, with a key crosswalk. It is the only option that fixes both defects at the source: every modern site is an official position, which +proj=calcofi reproduces to within 18 m, so all 213 sites sit on their line by construction; no cell is a remnant of an idealized lattice, so the slivers left are 1 between cells plus 131 water pockets the OSM coastline cuts off (185 km² in all); and no cell holds two official stations (today 13 cells do), which ends the station mixing that #86 and the climatology work routed around with site_key. Option B removes the slivers but keeps the nominal lattice (42 sites still more than 1 km off their line, 12 cells still holding several official stations); Option C moves the dots and nothing else, and cannot place 7 sites at all because their own line misses their cell.

The price of A is 17.0% of sample rows changing grid_key, 10.1% moving to a different cell rather than a renamed one (Table 8), and 86,711 of 777,501 climatology rows (44 stations) taking a new modal-cell label; the climatology means do not move (they are keyed on site_key), and the cell-month grain with three or more cruises grows from 513 to 602 because the inshore stations stop sharing cells. So the release that ships A needs a grid_key crosswalk (old to new, by largest overlap, as computed here) beside the per-dataset diff in RELEASES.md, and the answers to the questions below first.

## Why

Ben, 2026-10-02 ([CalCOFI/workflows#130](https://github.com/CalCOFI/workflows/issues/130)):
a grid point, i.e. a **site** (x: station, y: line), must land on its line, and the grid has
**slivers** (the [calcofi4r "CalCOFI grid"
figure](https://calcofi.io/calcofi4r/articles/calcofi4r.html#calcofi-grid); related
[#86](https://github.com/CalCOFI/workflows/issues/86) and
[CalCOFI/db-viz-station#19](https://github.com/CalCOFI/db-viz-station/issues/19)). Rather than
patch, start from the [official station
positions](https://calcofi.org/sampling-info/station-positions/) and build the cells as a Voronoi
tessellation of them.

This is an **exploration**, not an ingest. It has no `calcofi:` block, like every other
`explore_*.qmd`, so `build_targets_list()` never sees it: it is not a target, not a release
input, and it writes nothing to `cc_stage_dir()/parquet`. It changes no `grid_key`. It reads
the published release v2026.10.01 and writes only the downloaded station table (under
`cc_stage_dir()/reference/`) and this page.

  p <- x |> select(all_of(key)) |> st_cast("MULTIPOLYGON") |> st_cast("POLYGON", warn = FALSE)
  p$area_km2 <- as.numeric(st_area(p)) / 1e6
  p$width_km <- 2 * p$area_km2 / (as.numeric(st_length(st_cast(st_geometry(p), "MULTILINESTRING"))) / 1000)
  p |> group_by(across(all_of(key))) |>
    mutate(part = row_number(), n_parts = n(), largest = area_km2 == max(area_km2)) |> ungroup()
}
# a part is a sliver when it does not hold its cell's generator (the station it is the cell of)
# and it is thin or small
flag_slivers <- function(parts, gen, key = "grid_key") {
  gk  <- gen[[key]][match(parts[[key]], gen[[key]])]
  hit <- mapply(function(p, k) {
    gi <- which(gen[[key]] == k); length(gi) && st_intersects(p, st_geometry(gen)[gi], sparse = FALSE)[1, 1]
  }, st_geometry(parts), parts[[key]])
  parts$holds_gen <- hit
  parts$sliver    <- !hit & (parts$width_km < SLIVER_W | parts$area_km2 < SLIVER_A)
  # a sliver touching another cell is the visible defect; one touching none is a pocket of
  # water the land mask cuts off (a lagoon, a harbour) and stays with its cell
  nb <- st_is_within_distance(parts, parts, 50)
  parts$touches_other <- mapply(function(i, k) any(parts[[key]][i] != k), nb, parts[[key]])
  parts
}
# absorb every sliver into the neighbouring cell it shares the longest edge with,
# smallest first; a sliver with no neighbour keeps its key (reported)
absorb_slivers <- function(parts, key = "grid_key", tol_m = 50) {
  parts$key_new  <- parts[[key]]
  parts$shared_m <- NA_real_
  for (pid in order(parts$area_km2)) {
    if (!parts$sliver[pid]) next
    me     <- parts[pid, ]
    others <- which(parts$key_new != me$key_new)
    cand   <- others[st_intersects(st_buffer(st_geometry(me), tol_m), st_geometry(parts)[others], sparse = FALSE)[1, ]]
    if (!length(cand)) next
    bnd <- st_boundary(st_geometry(me))
    len <- vapply(cand, function(j) {
      x <- st_intersection(bnd, st_buffer(st_geometry(parts)[j], tol_m))
      if (!length(x) || all(st_is_empty(x))) 0 else sum(as.numeric(st_length(x)))
    }, numeric(1))
    if (max(len) <= 0) next
    parts$key_new[pid]  <- parts$key_new[cand[which.max(len)]]
    parts$shared_m[pid] <- max(len)
  }
  parts
}
# the first cell a point falls in (assign_grid_key()'s ST_Intersects ... LIMIT 1)
first_hit <- function(pts, cells, key = "grid_key") {
  ix <- st_intersects(pts, cells)
  vapply(ix, function(i) if (length(i)) cells[[key]][i[1]] else NA_character_, "")
}
# a site's distance from its line, km (+proj=calcofi via calcofi4db, never re-implemented)
off_line_km <- function(lon, lat, line) {
  p <- cc_lonlat_to_calcofi(lon, lat)
  abs(p$line - line) * KM_LINE
}

## How today's grid is built {#sec-today-build}

The release's `grid` table (218 cells) is `calcofi4db::build_grid_reference()`, which reads two
datasets bundled in **calcofi4r**, `cc_grid` (cells) and `cc_grid_ctrs` (sites), and names each
cell `st{station}-ln{line}` (`_hist` for the historical pattern). Every ingest then calls
`calcofi4db::assign_grid_key()`, a point-in-polygon `ST_Intersects … LIMIT 1` of the sample's
position against those cells, so `grid_key` on `sample` and `obs` is wherever the position falls.

`cc_grid` comes from `calcofi4r/data-raw/cc_grid.R`, which:

1. lays three **idealized lattices** in `+proj=calcofi` (line, station) coordinates, not the
   occupied positions: 5-unit spacing for stations ≤ 60 on the standard lines, 10-unit spacing
   offshore to station 120, and a 20-unit historical lattice out to the convex hull of every
   CTD cast;
2. takes a Voronoi tessellation of each lattice (in line/station units), cuts the finer ones
   out of the coarser, and hand-merges six historical pairs (e.g. 55/80 from 50/80 + 60/80);
3. keeps the cells listed in `data-raw/cc_grid_sta-keys.csv` and erases Natural Earth 10 m land
   (`st_difference`), which leaves gaps along the coast;
4. glues five of those gaps back onto line 93.3 cells by hand (`cc_grid_box4slivers.geojson`,
   `st_union` onto `93.3,30` … `93.3,110`), which is where the line-93.3 cells pick up second,
   detached parts;
5. makes the site of each cell `st_centroid(geom, of_largest_polygon = TRUE)` on lon/lat
   (`cc_grid_ctrs`; the release's `grid.geom_ctr`).

So a site is the centroid of whatever polygon survived steps 2–4, never a station position:
that is why sites leave their line wherever land, a merge or a glued gap reshaped the cell. And
the lattice is nominal (35, 40, 45, 50 …) while the occupied stations are not (90.0 37, 90.0 53,
80.0 51, 83.3 39.4 …), which is why an inshore cell holds several real stations.

## Option A: Voronoi of the official positions {#sec-option-a}

The generators are the `r nrow(st)` official positions. Outside the official pattern (beyond
the convex hull of the official stations buffered by 20 nm, half the offshore spacing) today's
cells are kept as generators at their labelled (line, station) under `+proj=calcofi`, so the
historical and Baja extent keeps a cell for every sample it holds today; a generator on land is
dropped. The Voronoi is taken in metres (California Albers), not in line/station units, which
weigh a line unit (22.2 km) and a station unit (7.4 km) alike. It is clipped to today's outer
hull (with interior holes filled) and to the OSM land mask, and then the coastline's leftovers
(pieces cut off by land that hold no station: the same sliver rule) are absorbed into the
neighbour they share the longest edge with.

**How offshore cells are bounded.** An official station on the edge of the pattern (station 100
to 120) is bounded seaward by the next historical generator, i.e. the 20-unit lattice, and
finally by today's outer hull, so an outer official cell reaches about halfway to the historical
lattice beyond it. The alternative (a fixed buffer around the official stations, with
everything beyond keyed only to the historical cells) is a question below.

## Option C: keep the cells, move each site onto its line {#sec-option-c}

`grid.geom_ctr` moves. A cell its own line does not cross cannot be fixed this way.

## Recommendation {#sec-recommendation}

**Option A**, with a key crosswalk. It is the only option that fixes both defects at the source:
every modern site *is* an official position, which `+proj=calcofi` reproduces to within
`r round(max(st$dist_m))` m, so all `r nrow(A)` sites sit on their line by construction; no cell
is a remnant of an idealized lattice, so the slivers left are `r hl$A[3]` between cells plus
`r hl$A[4]` water pockets the OSM coastline cuts off (`r fmt(pocket_km2_a)` km² in all); and no
cell holds two official stations (today `r hl$today[5]` cells do), which ends the station mixing
that #86 and the climatology work routed around with `site_key`. Option B removes the slivers
but keeps the nominal lattice (`r hl$B[2]` sites still more than `r OFF_KM` km off their line,
`r hl$B[5]` cells still holding several official stations); Option C moves the dots and nothing
else, and cannot place `r sum(!c_ok)` sites at all because their own line misses their cell.

The price of A is `r hl$A[6]` of `sample` rows changing `grid_key`, `r hl$A[7]` moving to a
different cell rather than a renamed one (@tbl-per-dataset), and `r fmt(ca$changed)` of
`r fmt(ca$n_rows)` climatology rows (`r ca$stations` stations) taking a new modal-cell label; the climatology means do not move (they are keyed
on `site_key`), and the cell-month grain with three or more cruises grows from
`r clim_tbl[[2]][1]` to `r clim_tbl[[2]][2]` because the inshore stations stop sharing cells. So
the release that ships A needs a `grid_key` crosswalk (old to new, by largest overlap, as
computed here) beside the per-dataset diff in `RELEASES.md`, and the answers to the questions
below first.
