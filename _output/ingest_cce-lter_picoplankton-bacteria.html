1 Overview

Source: Datazoo table download (https://oceaninformatics.ucsd.edu/datazoo/catalogs/ccelter/datasets/159/datatables/159/download), 16,017 rows, 16 columns (73 cruises, 2004-11-02 to 2023-07-18).

  • Provider: cce-lter (matches the existing provider group used by ingest_cce-lter_euphausiids/_zoodb/_zooscan – an earlier draft of this notebook used the unhyphenated ccelter, which would have created a duplicate, inconsistent provider group)
  • Grain: one row per bottle/depth per cast (station-level, multiple depths per cast)
  • Scope decision: no bounding-box filter applied – source is already scoped to CalCOFI/CCE cruises by the provider. studyName (e.g. 2004-11-02-C-33RR) is the cruise identifier used for key resolution, NOT the Cruise column (which is a separate YYYYMM short code, e.g. 200411 – kept as a raw field but not used for joins).
  • Completeness: Depth, Heterotrophic Bacteria, Synechococcus, and Picoeukaryotes are >99.9% populated. Prochlorococcus is ~80% populated (3,228/16,017 blank) – plausible non-detection at higher latitudes/depths, not yet confirmed with the provider (see Questions, Q01). Notes is 100% blank in the current export; it is read and normalized to NA rather than dropped, so a future export that starts populating it flows through without a schema change. No literal-zero values appear in any measurement column in this export (confirmed directly against the raw file) – unlike ZooDB, there is no analyzed-but-absent convention to encode; blank simply means not measured.

5 Pivot Measurements to Long Format

Unlike ZooDB, this source has no analyzed-but-absent convention – every blank cell in the raw export is genuinely not measured (confirmed: zero literal 0 values appear in Heterotrophic Bacteria or Prochlorococcus, only blanks). So this pivot simply drops NA, with no explicit-zero retention logic needed.

measurement_type codes are unit-less (het_bacteria, not het_bacteria_n_ml) – units live in measurement_type.csv’s units column, matching the convention used by bottle_measurement/ zoodb_measurement elsewhere in the DB. An earlier draft baked the unit into the type code itself; fixed here.

6 Register Measurement Types

Registers this dataset’s measurement_type codes into the shared metadata/measurement_type.csv and loads the measurement_type table into this connection – an earlier draft referenced measurement_type as a FK target in Schema Documentation / Validate without ever creating it, which would fail. Pattern matches ingest_calcofi_phyllosoma.qmd’s finalize step.

Two layers, since 2026-09-12 (measurement-faces plan D9, Ben’s decision):

  • The four source codes (synechococcus, prochlorococcus, picoeukaryotes, het_bacteria) stay in the registry and stay the vocabulary of the source-shaped picoplankton_bacteria_measurement table. They are not deleted – a registry row is statused, never removed – but from this render on they name a taxon, not an obs measurement type, so they stop appearing in obs_env and therefore in the measurements catalog at the next release.
  • One canonical type, picoplankton_abundance, is what obs carries. The organism moves into obs.taxon_key, which is what puts these counts under Biology beside every other cell count and gives Synechococcus and Prochlorococcus a species page. It is registered with register_measurement_types(), the helper that writes the registry with na = "" and keeps it sorted.
Code 
pb_types <- tribble(
  ~measurement_type, ~description,                              ~units,
  "het_bacteria",     "Heterotrophic bacteria abundance (FCM)",  "number/ml",
  "prochlorococcus",  "Prochlorococcus abundance (FCM); ~80% populated, see Q01", "number/ml",
  "synechococcus",    "Synechococcus abundance (FCM)",           "number/ml",
  "picoeukaryotes",   "Picoeukaryote abundance (FCM)",           "number/ml") |>
  mutate(is_canonical = TRUE,
         grain        = "obs",
         `_source_column` = case_when(
           measurement_type == "het_bacteria"    ~ "Heterotrophic Bacteria (number/ml)",
           measurement_type == "prochlorococcus" ~ "Prochlorococcus (number/ml)",
           measurement_type == "synechococcus"   ~ "Synechococcus (number/ml)",
           measurement_type == "picoeukaryotes"  ~ "Picoeukaryotes (number/ml)"),
         `_source_table` = "picoplankton_bacteria_measurement",
         `_source_datasets` = "cce-lter_picoplankton-bacteria",
         `_qual_column` = NA_character_, `_prec_column` = NA_character_)

# upsert so a units/description correction propagates on re-run, and keep the
# registry sorted so its on-disk order is deterministic across ingests
# upsert, not delete-and-replace: the literal below carries no valid_min/
# valid_max, and the naive `filter(!= x) |> bind_rows()` destroyed those
# curated bounds on every re-run (it silently un-declared euphausiid_abundance
# and the picoplankton types mid-release, failing the bounds gate).
d_meas_type <- upsert_measurement_types(d_meas_type, pb_types)
new_types <- pb_types
write_csv(d_meas_type, meas_type_csv, na = "")

# the canonical type `obs` carries. One quantity -- cells per millilitre by flow
# cytometry -- for all four populations; WHICH population is `obs.taxon_key`, not
# a suffix on the type name. No `nerc_p01`: P700A90Z / P701A90Z each name one
# organism's count, so neither is an exact concept for the pooled type, and an
# inexact controlled-vocabulary id is left empty by the registry rule. The two
# organism-specific P01s stay on their own rows above, where they are exact.
pb_canonical <- tribble(
  ~measurement_type,        ~description, ~units,
  "picoplankton_abundance",
  paste("Picoplankton and bacteria cell abundance by flow cytometry (FCM);",
        "the population counted is obs.taxon_key"),
  "number/ml") |>
  mutate(valid_min = 0, is_canonical = TRUE, grain = "obs",

         `_source_column` = paste(
           "Synechococcus (number/ml)", "Prochlorococcus (number/ml)",
           "Picoeukaryotes (number/ml)", "Heterotrophic Bacteria (number/ml)",

         `_source_datasets` = "cce-lter_picoplankton-bacteria",
         `_qual_column` = NA_character_, `_prec_column` = NA_character_,
         units_nerc_p06 = "http://vocab.nerc.ac.uk/collection/P06/current/UCML/")
d_meas_type <- register_measurement_types(pb_canonical, meas_type_csv)

13 Emit Core Tables

Project this dataset into the shared consolidated core model (design_env-bio-consolidation.md), the same projection release_database.qmd uses to assemble the cross-dataset release. This is a bottle-shaped sample — leaf grain bottle_id, and since the export carries no cast-level event table the bottle is its own root — with an obs headline of the four flow-cytometry counts.

Realm bio, since 2026-09-12 (measurement-faces plan D9; Ben: these counts belong under Biology, where the datasets catalog already files this dataset). Until then the arm emitted realm = 'env' with a NULL taxon_key, on the reading that “the four FCM types ARE the measurement vocabulary”. They are not: each one names an organism counted by the same instrument in the same units. So the quantity is one canonical measurement_type (picoplankton_abundance, cells per ml) and the organism is obs.taxon_key — which is the shape every other cell count in the database already has, and the only shape that reaches build_taxa_catalog() (it reads obs_bio) so that /species/worms-160572/ is a page rather than a 404.

Two of the four populations are genera an authority keys — Synechococcus (WoRMS 160572) and Prochlorococcus (WoRMS 345515), the same organisms NERC’s S25 attaches to the P01s P700A90Z and P701A90Z on the two registry rows. The other two, picoeukaryotes and het_bacteria, are operational classes: a size fraction of the eukaryotes and a trophic fraction of the bacteria, neither of which is a taxon. Their identity is not dropped — they take a dataset-local taxon_key (cce-lter_picoplankton-bacteria:picoeukaryotes, …:het_bacteria) declared one at a time in local_allow below and in release_database.qmd’s TAXON_LOCAL_ALLOW, exactly as ZooScan’s eggs / multiples / nauplii / others and phytoplankton’s undefined codes do. That is the established mechanism for a real class in the source that no authority can key; check_taxon_ids() fails the release on any dataset-local key not on that list, so a genuinely unresolved taxon cannot hide among them.

## Overview

**Source**: Datazoo table download (`https://oceaninformatics.ucsd.edu/datazoo/catalogs/ccelter/datasets/159/datatables/159/download`),
16,017 rows, 16 columns (73 cruises, 2004-11-02 to 2023-07-18).

- **Provider**: `cce-lter` (matches the existing provider group used by
  `ingest_cce-lter_euphausiids`/`_zoodb`/`_zooscan` -- an earlier draft of
  this notebook used the unhyphenated `ccelter`, which would have created a
  duplicate, inconsistent provider group)
- **Grain**: one row per bottle/depth per cast (station-level, multiple depths per cast)
- **Scope decision**: no bounding-box filter applied -- source is already
  scoped to CalCOFI/CCE cruises by the provider. `studyName` (e.g.
  `2004-11-02-C-33RR`) is the cruise identifier used for key resolution, NOT
  the `Cruise` column (which is a separate YYYYMM short code, e.g. `200411`
  -- kept as a raw field but not used for joins).
- **Completeness**: Depth, Heterotrophic Bacteria, Synechococcus, and
  Picoeukaryotes are >99.9% populated. Prochlorococcus is ~80% populated
  (3,228/16,017 blank) -- plausible non-detection at higher latitudes/depths,
  not yet confirmed with the provider (see Questions, Q01). `Notes` is 100%
  blank in the current export; it is read and normalized to `NA` rather than
  dropped, so a future export that starts populating it flows through without a
  schema change. No literal-zero values appear
  in any measurement column in this export (confirmed directly against the
  raw file) -- unlike ZooDB, there is no analyzed-but-absent convention to
  encode; blank simply means not measured.

## Pivot Measurements to Long Format

Unlike ZooDB, this source has no analyzed-but-absent convention -- every
blank cell in the raw export is genuinely not measured (confirmed: zero
literal `0` values appear in Heterotrophic Bacteria or Prochlorococcus,
only blanks). So this pivot simply drops NA, with no explicit-zero
retention logic needed.

`measurement_type` codes are unit-less (`het_bacteria`, not
`het_bacteria_n_ml`) -- units live in `measurement_type.csv`'s `units`
column, matching the convention used by `bottle_measurement`/
`zoodb_measurement` elsewhere in the DB. An earlier draft baked the unit
into the type code itself; fixed here.

## Register Measurement Types

Registers this dataset's `measurement_type` codes into the shared
`metadata/measurement_type.csv` and loads the `measurement_type` table into
this connection -- an earlier draft referenced `measurement_type` as a FK
target in Schema Documentation / Validate without ever creating it, which
would fail. Pattern matches `ingest_calcofi_phyllosoma.qmd`'s `finalize` step.

Two layers, since 2026-09-12 (measurement-faces plan D9, Ben's decision):

- The **four source codes** (`synechococcus`, `prochlorococcus`,
  `picoeukaryotes`, `het_bacteria`) stay in the registry and stay the vocabulary
  of the source-shaped `picoplankton_bacteria_measurement` table. They are **not
  deleted** -- a registry row is statused, never removed -- but from this render
  on they name a *taxon*, not an `obs` measurement type, so they stop appearing
  in `obs_env` and therefore in the measurements catalog at the next release.
- One **canonical type**, `picoplankton_abundance`, is what `obs` carries. The
  organism moves into `obs.taxon_key`, which is what puts these counts under
  Biology beside every other cell count and gives *Synechococcus* and
  *Prochlorococcus* a species page. It is registered with
  `register_measurement_types()`, the helper that writes the registry with
  `na = ""` and keeps it sorted.

```{r}
#| label: register-measurement-types
pb_types <- tribble(
  ~measurement_type, ~description,                              ~units,
  "het_bacteria",     "Heterotrophic bacteria abundance (FCM)",  "number/ml",

  "synechococcus",    "Synechococcus abundance (FCM)",           "number/ml",
  "picoeukaryotes",   "Picoeukaryote abundance (FCM)",           "number/ml") |>
  mutate(is_canonical = TRUE,
         grain        = "obs",
         `_source_column` = case_when(
           measurement_type == "het_bacteria"    ~ "Heterotrophic Bacteria (number/ml)",
           measurement_type == "prochlorococcus" ~ "Prochlorococcus (number/ml)",
           measurement_type == "synechococcus"   ~ "Synechococcus (number/ml)",
           measurement_type == "picoeukaryotes"  ~ "Picoeukaryotes (number/ml)"),
         `_source_table` = "picoplankton_bacteria_measurement",
         `_source_datasets` = "cce-lter_picoplankton-bacteria",
         `_qual_column` = NA_character_, `_prec_column` = NA_character_)

# registry sorted so its on-disk order is deterministic across ingests
# upsert, not delete-and-replace: the literal below carries no valid_min/
# valid_max, and the naive `filter(!= x) |> bind_rows()` destroyed those
```

## Resolve Ship and Cruise Keys

`cruise_key` in the shared `cruise` table is a natural key in format
`YYYY-MM-NODC`, built by the real `calcofi4db::derive_cruise_key_on_casts()`
function (confirmed from `ship.R`). That function needs a `ship_code` column
(matched against `ship.ship_nodc`) and a `datetime_utc` column, and accepts
the target table directly via `table_name=` (confirmed via
`ingest_calcofi_mets.qmd`'s usage) -- no need to rename anything to `casts`.
This source has no `ship_code` natively -- only `studyName` (e.g.
`2004-11-02-C-33RR`), whose trailing code (`33RR`) is the ship code embedded
in the string -- so extract that into a `ship_code` column, then call the
real function against `picoplankton_bacteria_bottle` directly rather than
reimplementing its SQL by hand (an earlier draft did this incorrectly).

## Emit Core Tables

Project this dataset into the shared consolidated core model
(`design_env-bio-consolidation.md`), the
same projection `release_database.qmd` uses to assemble the cross-dataset
release. This is a bottle-shaped sample — leaf grain `bottle_id`, and since the
export carries no cast-level event table the bottle is its own root — with an
`obs` headline of the four flow-cytometry counts.

**Realm `bio`, since 2026-09-12** (measurement-faces plan D9; Ben: these counts
belong under Biology, where the datasets catalog already files this dataset).
Until then the arm emitted `realm = 'env'` with a NULL `taxon_key`, on the
reading that "the four FCM types ARE the measurement vocabulary". They are not:
each one names an *organism* counted by the same instrument in the same units.
So the quantity is one canonical `measurement_type`
(`picoplankton_abundance`, cells per ml) and the organism is
`obs.taxon_key` — which is the shape every other cell count in the database
already has, and the only shape that reaches
`build_taxa_catalog()` (it reads `obs_bio`) so that
`/species/worms-160572/` is a page rather than a 404.

Two of the four populations are genera an authority keys — *Synechococcus*
(WoRMS 160572) and *Prochlorococcus* (WoRMS 345515), the same organisms NERC's
S25 attaches to the P01s `P700A90Z` and `P701A90Z` on the two registry rows.
The other two, `picoeukaryotes` and `het_bacteria`, are **operational classes**:
a size fraction of the eukaryotes and a trophic fraction of the bacteria, neither
of which is a taxon. Their identity is **not** dropped — they take a
dataset-local `taxon_key` (`cce-lter_picoplankton-bacteria:picoeukaryotes`,
`…:het_bacteria`) declared one at a time in `local_allow` below and in
`release_database.qmd`'s `TAXON_LOCAL_ALLOW`, exactly as ZooScan's
eggs / multiples / nauplii / others and phytoplankton's undefined codes do. That
is the established mechanism for a real class in the source that no authority can
key; `check_taxon_ids()` fails the release on any dataset-local key not on that
list, so a genuinely unresolved taxon cannot hide among them.

```{r}
#| label: emit_core

ds_key <- "cce-lter_picoplankton-bacteria"
# filter the crosswalk to THIS dataset -- an unfiltered read leaks other datasets'
# taxa into this shard. This dataset has no measurement_taxon.csv rows: the
# composite-decomposition registry is for an ingest whose taxon comes ONLY from a
# measurement_type name (cufes, phyllosoma, dungeness crab). Here the vocabulary
# is declared with append_dataset_taxon() instead, because that is the only path
# that mints a dataset-local key for the two operational classes -- and two
# sources of truth for one taxon_key is what the taxon plan's D1 removed.
mt_taxon <- read_csv(here("metadata/measurement_taxon.csv"),
                     col_types = cols(worms_id = "i", itis_id = "i",
                                      bin_value = "d", .default = "c")) |>
  filter(dataset_key == ds_key)
tx_over  <- read_csv(here("metadata/taxon_override.csv"), show_col_types = FALSE)

# This projection lives here, in the notebook that owns the dataset, not in a
# switch(dataset_key, ...) arm inside calcofi4db. The reusable SHAPES stay in the
# package (sample_arm_self / compat_measurement_sql), so this is a declaration.
#
# The vocabulary is DECLARED here and RESOLVED by the package (taxon plan D1,
# calcofi4db >= 3.29.0): append_dataset_taxon() stages one `dataset_taxon` row
# per source code with `taxon_key` empty and the AphiaID we supply carried along
# as `ds_source_json`; resolve_dataset_taxon() fills the key from the authorities
# and mints a dataset-local key where no authority answers. `ds_taxa_code` is the
# source's own measurement column name, VERBATIM, because that is what the
# measurement rows join on -- rewriting it would orphan every observation.
#
# The two AphiaIDs are not guesses: they are what NERC's S25 (biological entity)
# concept behind each P01 is owl:sameAs (probed 2026-09-11,
# .claude/plans/2026-09-11 measurement-faces-probe/nvs_probe.json).
d_vocab <- tibble::tribble(
  ~ds_taxa_code,      ~ds_scientific_name, ~ds_common_name,            ~worms_id, ~rank,
  # no ds_common_name for the two genera: the source supplies no vernacular, and
  # repeating the scientific name as a "common name" would publish one we invented
  "synechococcus",    "Synechococcus",     NA_character_,              160572L,   "Genus",
  "prochlorococcus",  "Prochlorococcus",   NA_character_,              345515L,   "Genus",
  # no scientific name to look up: a size class and a trophic class, not taxa
  "picoeukaryotes",   NA_character_,       "picoeukaryotes",           NA_integer_, NA_character_,
  "het_bacteria",     NA_character_,       "heterotrophic bacteria",   NA_integer_, NA_character_)
n_staged <- append_dataset_taxon(con, ds_key, d_vocab)

# cross-reference: resolve each taxon against BOTH authorities (cached in
# metadata/taxon_xref.csv, so a re-run costs no API calls). This fills the
# `worms_id` COLUMN on itis:-keyed taxa without touching their key, backfills
# `itis_id` the other way, replaces an id its authority has deprecated so the key
# is always an accepted id, and fetches the real `taxonomic_status` with the date
# it was checked. Must precede the lineage fetch, which should ask about the
# accepted id, not the deprecated one.
ensure_taxon_xref(con, mt_taxon, tx_over,
                  cache_csv = here("metadata/taxon_xref.csv"))

# lineage: fetch each taxon's WoRMS classification (cached in
# metadata/taxon_lineage.csv) and stage it as the `taxon` hierarchy
# build_taxon_reference() reads. Without it a taxon reaches the release with a
# key and a name and NOTHING else -- no rank, no parent_taxon_key, no
# classification -- so hierarchy rollups silently match nothing.
ensure_taxon_lineage(con, mt_taxon, tx_over,
                     cache_csv = here("metadata/taxon_lineage.csv"))
n_taxon    <- build_taxon_reference(con, mt_taxon, tx_over)
n_ds_taxon <- resolve_dataset_taxon(con, mt_taxon, tx_over)
n_tx_group <- build_taxon_group(con, read_taxon_group_rules(here("metadata/taxon_group.csv")))

# the ingest asserts its own crosswalk (D6). Two of the four populations are
# OPERATIONAL, not taxonomic, so they key dataset-locally BY DECLARATION -- one
# key at a time, with the reason, so a genuinely unresolved taxon cannot hide
# among them. The same two keys are declared in release_database.qmd's
# TAXON_LOCAL_ALLOW, which is the gate that fails the release.
local_allow <- tibble::tribble(
  ~ds_taxa_code,    ~why,
  "picoeukaryotes", "a <2-3 um SIZE fraction of the eukaryotic plankton, not a taxon",
  "het_bacteria",   "the heterotrophic (non-cyanobacterial) fraction of the bacteria, a TROPHIC class")
obs_codes <- dbGetQuery(con,
  "SELECT DISTINCT measurement_type AS c FROM picoplankton_bacteria_measurement")$c
chk_taxon <- check_dataset_taxon(
  con, ds_key, allow = paste0(ds_key, ":", local_allow$ds_taxa_code),
  codes = obs_codes)
cat(glue("vocabulary: {n_staged} populations staged; {nrow(local_allow)} keyed ",
         "dataset-locally by declaration; taxon {n_taxon}, ",
         "dataset_taxon {n_ds_taxon}, taxon_group {n_tx_group}"), "\n")

append_sample(con, sample_arm_self(
  ds_key, "picoplankton_bacteria_bottle", "bottle_id", "bottle",
  dt_col = "datetime_utc", site_expr = "site_key",
  depth_min = "depth_m", depth_max = "depth_m"))

# realm 'bio'; ONE measurement_type for the quantity, the organism in taxon_key.
# The join to dataset_taxon is INNER on purpose: a source column that never
# reached the vocabulary would silently vanish from obs, and the parity assert
# below (n_obs == every measurement row) is what catches it.
append_obs(con, glue("
  SELECT 'bio', '{ds_key}', {ns_key(ds_key, 'bottle', 'b.bottle_id')},
         b.grid_key, b.cruise_key, b.latitude, b.longitude,
         CAST(b.datetime_utc AS TIMESTAMP), b.depth_m, b.depth_m,
         dt.taxon_key, NULL::VARCHAR, 'picoplankton_abundance', m.measurement_value,
         NULL::VARCHAR, NULL::DOUBLE
  FROM picoplankton_bacteria_measurement m
  JOIN picoplankton_bacteria_bottle b USING (bottle_id)
  JOIN dataset_taxon dt ON dt.dataset_key = '{ds_key}'
                       AND dt.ds_taxa_code = m.measurement_type"))

core <- list(
  sample        = dbGetQuery(con, "SELECT COUNT(*) FROM sample")[[1]],
  obs           = dbGetQuery(con, "SELECT COUNT(*) FROM obs")[[1]],
  taxon         = n_taxon,
  dataset_taxon = n_ds_taxon,
  taxon_group   = n_tx_group)
cat(glue(
  "core projection — sample={core$sample %||% 0} obs={core$obs %||% 0} ",
  "taxon={core$taxon %||% 0} dataset_taxon={core$dataset_taxon %||% 0} ",
  "taxon_group={core$taxon_group %||% 0}\n"))

# every measurement on a bottle must reach obs, and must reach it WITH a taxon
n_obs <- dbGetQuery(con, "SELECT COUNT(*) FROM obs")[[1]]
n_exp <- dbGetQuery(con,
  "SELECT COUNT(*) FROM picoplankton_bacteria_measurement m
   JOIN picoplankton_bacteria_bottle b USING (bottle_id)")[[1]]
stopifnot(
  "obs must be one row per measurement" = n_obs == n_exp,
  "every picoplankton obs must carry a taxon_key" =
    dbGetQuery(con, "SELECT COUNT(*) FROM obs WHERE taxon_key IS NULL")[[1]] == 0,
  "obs must carry exactly one measurement_type" =
    dbGetQuery(con, "SELECT COUNT(DISTINCT measurement_type) FROM obs")[[1]] == 1)
cat(glue("obs parity: {format(n_obs, big.mark=',')} rows, all taxon-resolved"), "\n")

dbGetQuery(con, "
  SELECT o.taxon_key, t.scientific_name, t.rank, COUNT(*) AS n_obs,
         COUNT(*) FILTER (WHERE o.measurement_value > 0) AS n_present,
         MIN(year(o.datetime)) AS year_min, MAX(year(o.datetime)) AS year_max
  FROM obs o LEFT JOIN taxon t USING (taxon_key)
  GROUP BY ALL ORDER BY n_obs DESC") |>
  datatable(caption = paste(
    "obs by taxon — what the species catalog will count. The two genera get a",
    "page at /species/worms-160572/ and /species/worms-345515/; the two",
    "operational classes keep their identity in a declared dataset-local key."),
    rownames = FALSE)

stopifnot(
  "every obs.sample_key must resolve in sample" =
    dbGetQuery(con, "SELECT COUNT(*) FROM obs o LEFT JOIN sample s USING (sample_key)
                     WHERE s.sample_key IS NULL")[[1]] == 0)
# serve the retired per-dataset table name as a VIEW over the core, so
# in-notebook consumers and ad-hoc queries keep working against the old name.
# Written out rather than taken from compat_measurement_sql(): that shape returns
# obs.measurement_type, which is now the canonical `picoplankton_abundance` for
# every row, so the view would lose the very thing this table is keyed by. The
# source's own column name comes back from dataset_taxon.ds_taxa_code, which is
# where it is now stored verbatim.
invisible(dbExecute(con, "DROP TABLE IF EXISTS picoplankton_bacteria_measurement_src"))
invisible(dbExecute(con, "ALTER TABLE picoplankton_bacteria_measurement RENAME TO picoplankton_bacteria_measurement_src"))
invisible(dbExecute(con, glue(
  "CREATE OR REPLACE VIEW picoplankton_bacteria_measurement AS
   SELECT o.obs_id                          AS measurement_id,
          split_part(o.sample_key, ':', 3)  AS bottle_id,
          dt.ds_taxa_code                   AS measurement_type,
          o.measurement_value, o.measurement_qual
   FROM obs o
   LEFT JOIN dataset_taxon dt ON dt.dataset_key = '{ds_key}'
                             AND dt.taxon_key   = o.taxon_key
   WHERE o.dataset_key = '{ds_key}'")))
cat(glue("compat view picoplankton_bacteria_measurement over obs: ",
         "{dbGetQuery(con, 'SELECT COUNT(*) FROM picoplankton_bacteria_measurement')[[1]]} rows"), "\n")
```
