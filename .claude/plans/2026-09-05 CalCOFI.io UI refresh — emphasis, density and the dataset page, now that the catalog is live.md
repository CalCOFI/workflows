## The ask (Ben, 2026-09-05)

Refresh the calcofi.io UI around the datasets that landed today, exhaustively and creatively, referring to and if
needed updating brand v2, and getting **emphasis** right. His examples: on `/datasets/` the holdings "not yet in
the integrated database" carry more emphasis than the datasets above them, in both themes; the category cards
vary so much in height that the grid is mostly empty space. On a dataset page (`/datasets/calcofi_ctd-cast/`)
the extent map is a bbox over faint grey dots with no basemap and no theme response; a massive gap sits between
the abstract and Access; some Explore links open the dataset and the rest only the app, so the URL should show;
Download is a confusing list with no grouping by source (ERDDAP) or format (parquet) and no explanation of
obs vs sample; Services never says ERDDAP; Archives & portals should list the identifier and/or title.

## Goal

A visitor scanning `/datasets/` sees the sixteen integrated datasets first and the holdings second, in a grid
that is content and not air; a visitor on a dataset page sees the dataset where it was sampled, over a coast,
and finds every way in grouped by *how*, each way named by its source and its identifier, with the URL in
view; a holding page says where the data live today. All of it on brand v2's tokens, both themes, Lighthouse
accessibility 100, and all of it still generated from the record.

## Non-goals

A JavaScript framework; a map library on the dataset page (the map stays a static SVG built at Jekyll time);
restyling any brand v2 token or class (additions only — v3 is not opened here); any dataset fact typed into the
site repo; changing the products (cards) beyond the `dataset_url` template; the release itself (Phase D's
record fields ride whatever release comes next; the site degrades to its fallbacks until then).

## Design

### D-1 · Emphasis is a ladder, and yellow is reserved

Four rungs, each defined by tokens so both themes follow (§ D-8 adds the two chip classes the ladder needs):

| rung | what | name | weight | leading mark | chips | example |
|---|---|---|---|---|---|---|
| 1 | a dataset in the release | `--accent` | 700 | its `color` as a 9 px dot | provider (outline) · format as one mono phrase `parquet · netCDF · ERDDAP` · licence when present | CTD Cast Files |
| 2 | a contribution from a dataset homed elsewhere | `--fg` | 400, italic "contributes" | hollow dot in the dataset's colour | the variables **collapsed** to "n variables ▸" (a `<details>`; the names stay in the DOM for search) | Hydrographic Bottle under Nutrients |
| 3 | a holding, not in the database | `--muted` | 400 | none | provider and stage as **quiet** chips (no border, no colour); source ↗ | PRODO under Productivity |
| 4 | a reference row (cruise, grid, a layer) | `--fg` | 400 | none | count in mono | Grid · 218 rows |

Rules that follow: `--warn` (gold / yellow) marks only a state needing attention — a product's *interim*
badge, a `planned` registration with an open issue, a `superseded` endpoint — never a kind of thing (a holding,
a pipeline stage). A pipeline stage (`ingested`, `validated`, `metadata`, `published`; `external`, `archived`
for holdings) is information, not a warning: neutral chips, `published` in the *ok* tint. The colour of a link
is the accent everywhere except rung 3, where the muted link keeps its underline on hover so it is still
recognisably a link (WCAG 1.4.1 holds because the row's only text is the link).

### D-2 · The grid packs; the reference frame gets its own band

- **Packing**: the grid keeps `category.order` and two columns — the artifact's *how the tiles stack* schematic
  draws all 14 tiles at their measured heights, today's row-stretch beside the masonry placement (each tile
  under the shorter column, in DOM order), because one tile cannot show a layout (Ben, round 2); a 40-line `assets/masonry.js` sets each tile's
  `grid-row-end: span n` from its measured height on load, on resize and after `document.fonts.ready`
  (`grid-auto-rows: 8px`, the 24 px gap folded into the span). No-JS fallback is `align-items: start`. When
  `grid-template-rows: masonry` is available the script does nothing (feature-detect with
  `CSS.supports("grid-template-rows", "masonry")`). Reading order is unchanged: the tiles stay in DOM order;
  masonry only fills the vertical.
- **The reference tile leaves the grid** and becomes a full-width band under it — *The reference frame* — three
  columns: the five tables · the 19 layers grouped (Maritime Zones, Protected Areas, Administrative, Ecological,
  Energy & Industry) · the bathymetry. It is the one tile whose rows are not datasets (catalog plan Decision 20),
  and it is the tile that doubled the grid's height. The filter row ignores it, as now.
- **Tile anatomy** (top to bottom): icon + name + the category's one-line description in `--muted`
  (`category.description`, § D-9 puts it in the record; until then omitted, never typed here); the count eyebrow
  as now; rung-1 rows; rung-2 rows; the holdings under a quiet separator "not yet in the database · n", **at
  most four shown**, the rest behind "and n more ▸". A dataset row's meta is one line at 549 px: provider chip ·
  years · sparkline · n obs · `parquet · netCDF · ERDDAP` as one mono phrase (the format chips were three chips
  and a wrap).
- **The sparkline** stays (74 × 14 px) and gains `<title>` text (years, peak year) — free hover, no JS.
- **A list view** (Phase G): a toggle *By category · List* over the same rows — one sortable table (name,
  category, provider, years, obs, formats, stage) — the accessibility "table view" and the fastest scan of 33
  records; the state persists in `localStorage`.

### D-3 · Holdings are present and quiet

Rung 3 as above, plus: the name is `dataset_name_short` when the record has one and the full `dataset_name` in
`title=` (and the full name is what search matches); a holding with neither short name nor a one-line name is
clamped to one line with an ellipsis. On a holding's page the h1 is the short name and the full name becomes the
lede under it (`.cc-lede`); a page whose only name is longer than 80 characters sets the h1 at the h2 size
(`.ds-title-long`, computed at build), so Teko never runs six lines. The head note *Not yet in the integrated
database* stays, in `--muted`, not in a warning colour.

### D-4 · The dataset page — the map is the hero, and nothing below it is two columns

Ben's review of the first mock (2026-09-05, round 2) found the proposed Overview still 600 px out of balance:
a two-column region whose columns are an abstract of unknown length and a map of fixed height can never be made
to end together. So no section below the head is two columns. Order, top to bottom, page scale:

1. **Head band** (Sand) — **the map is the hero image**: left, breadcrumb · icon + title (+ lede when the
   short/full split applies) · chips (key with its colour dot · provider · licence · DOI · release · stage) ·
   the *at a glance* stat grid (3 × 2: years · observations · sampling events · stations · variables or taxa ·
   depth) · the years sparkline with its caption; right, the map (§ D-5) **bounded to the title block's height**
   (round 3, Ben): the map cell stretches to the grid row and the SVG fits inside it (`position: absolute; inset: 0`
   in a `minmax(0, 1fr)` cell, `preserveAspectRatio="xMaxYMin meet"`, the water rect inside the drawing and no
   background on the element), so it is exactly as tall as the text beside it — about 400 px at 1170 — and never
   taller; on a phone the cell takes the drawing's aspect ratio and the map follows the title block. A holding
   has no map and gets the title block alone. *Alternative kept in reserve if the bounded map reads small:* the
   map floats right across the head and the Overview so the description wraps beneath it (a magazine layout; the
   sub-nav would then sit above the head).
2. **Sub-nav**: a sticky uppercase tab row — *Overview · Coverage · Access · Cite · Provenance · Related* —
   the landing page's `.section-tabs` idiom promoted to brand (`.cc-tabs`, § D-8).
3. **Overview** — one column: description at 72 ch, PIs / creators / contact / funding, keywords, the open
   provider questions, the head links. Its height is whatever the abstract needs; nothing sits beside it.
4. **Coverage band** — the variables as chips, `name` with `units` beside it and the NERC P01 URI in `title=`
   once the record's `variables[]` are objects (the layout handles both shapes, see Risks), **collapsed past 16**
   behind "all 33 ▸"; taxa (top 50 with common names and `n_obs`, next release) as a two-column list; life
   stages; "also contributes to". Each variable chip links into the Explorer as now.
5. **Access** (§ D-6), on the Sand band — rows, not columns.
6. **Cite**, **Provenance**, **Related** — Cite and Provenance keep their side-by-side layout (both are short
   and bounded: a citation block beside a definition list) with `align-items: start`, plus copy buttons.

The alternative kept in reserve: the stat strip full width under the head and the map bounded to 340 px beside
the description, with the coverage chips joining the main column to fill — balanced for the CTD casts, not for a
two-sentence abstract. The hero map is the layout that cannot go wrong.

### D-5 · The map shows where the dataset is, over a coast, in both themes

A static inline SVG drawn by `_plugins/datasets.rb` at build, no library, tokens only:

- **Land** from `_data/land.geojson` — Natural Earth 1:50 m land (public domain) clipped to 135–105° W ×
  19–49° N and simplified to 0.012° by `scripts/build_land.py` (a one-off; the file is committed: it is
  cartography, not a dataset fact). Prototyped 2026-09-05: 1,420 NE features → the coast of California and
  Baja plus the Channel Islands in a few KB (§ Measured).
- **Water** `--cc-map-water`, land `--cc-map-land` with a `--cc-map-coast` stroke, the grid centroids in
  `--cc-map-grid` (every cell, hollow), **the stations this dataset sampled as filled marks in the accent,
  radius ∝ √n_obs** (from `coverage_stations.json`, fetched by `fetch_release.sh` beside the record — it is a
  release sidecar), the record's bbox as a thin dashed rectangle, a 5° graticule as edge ticks (`30° N`,
  `120° W`), and a `<title>` per sampled station (`st90-ln80 · 415,649 obs`) for free hover.
- **The frame** is the standard + extended grid ∪ the sampled stations, padded 6 % — never the raw bbox. A bbox
  that reaches beyond the frame is clipped and the map says *extent continues beyond the frame* in its corner;
  that is what the ichthyoplankton's 0–54° N record bbox gets until the coordinates are fixed upstream (Open
  question 2). The historical lines to 48° N draw only when the dataset sampled them.
- **Theme**: everything is a class on a token, so the toggle repaints it. Light: water `#e6eef4`, land the Sand
  `#f5f0e6`, coast `--muted`, marks `--accent`; dark: water `--bg`, land `--panel-2`, coast `--muted`, marks
  `--accent`. Contrast of the marks on the water: 5.6 : 1 light, 7.6 : 1 dark (Appendix B).
- The same drawing, without the stations, becomes the reference band's map of the grid.

### D-6 · Access — rows that span the page, one listing per source, the URL always in view

Round 2 (Ben): URLs placed in a right-hand column wrap hideously on a phone; ERDDAP listed twice (Download's
formats + page + info, then Services' tabledap + info) is confusing; the SQL should reach db-query's shell.

**The row.** Every Access row is two lines that span the full width: line 1 — the label, its chips, its meta
and the copy button, wrapping as needed; line 2 — **the URL**, mono, on its own line, **middle-elided** so it
never wraps: the plugin splits it into a head (`https://storage.googleapis.com/…/tables/obs/`) that shrinks with
`text-overflow: ellipsis` and a tail (`data_0.parquet`, `?datasets=calcofi_ctd-cast`) that never shrinks, so the
informative end is visible at 375 px and the whole URL is in `title=` and one tap away on the copy button.
No table columns anywhere in Access except the ERDDAP matrix, which is a CSS grid that folds to one id per row
on a phone. (Today's `.ds-table` `th` at 34 % is what put code and URLs in a right-hand column.)

**The groups** — six again, but Download and Services merge so ERDDAP appears **once**:

- **Explore** — one row per app: name · *opens on* chip (**this dataset** for a deep link, **the app** when
  not, with the reason) · the URL line. Deep links come from a `dataset_url:` template on the product in
  `products.yml` (`https://calcofi.io/explore/?datasets={key}`, `https://app.calcofi.io/cruise/?datasets={key}`);
  Phase E adds the Station Explorer's `?dataset=` and the Hexagon Explorer's bookmark. `products.yml` stays the
  one place a product-to-dataset link is written.
- **Query** — db-query opens the dataset's saved query when one exists (`#datasets--bottle`), otherwise **the SQL
  shell with the dataset's SQL prefilled** — a `?sql=` parameter db-query does not read yet: today the app reads
  nothing from the URL but the `#queryId` hash (`showQuery(location.hash)`); Phase E has `app.js` read
  `location.search` once on load, put `sql` into the shell's `<textarea name="sql">` (`_includes/form-field.html`)
  and show that section (`#sql-shell--shell`; query ids are `category--name`), and never write values back into
  the URL. The snippet targets the first of the
  dataset's tables that carries `dataset_key` (`obs`, else `sample`) and uses db-query's `__TBL:obs__` token so it
  resolves to the pinned release.
- **Code** — R, Python, and **DuckDB anywhere**: `SELECT * FROM read_parquet('<object URL>')`.
- **Get the data** — one block per source, each with a lede:
  1. *Files from the release (Parquet)* — one row per object: table · scope (*this dataset's rows* / *whole table,
     shared*) · bytes · `since` · sha256 (copy) · the URL line.
  2. *CF netCDF* — the file (and *full*) · bytes · sha256 · the CF note in a `<details>` · the URL line.
  3. *ERDDAP (erddap.calcofi.io)* — **the one ERDDAP listing**: a matrix, one row per ERDDAP dataset id — the id
     in mono · its grain · CSV · netCDF · JSON · **page · info · graph** — so the service links live with the
     format links and nothing repeats. Under it the grain glossary (`grain_description` from the record, § D-9;
     the site's fallback until then) and, muted, the legacy ids with "replaced by …" and the sunset date.
  4. *From the provider* — the source download with the portal's name.
- **Metadata records** — ISO 19115-3 (ERDDAP WAF), FGDC (`/erddap/metadata/fgdc/xml/{id}_fgdc.xml`), this page's
  JSON-LD and record JSON, the DCAT entry, the STAC collection when the release carries it. Records about the
  data, separated from the data.
- **Archives & portals** — one row per registration or external record: portal (linking, with its
  description in `title=`) · **identifier** in mono · title · status chip. The identifier is
  `registrations[].id` / `distributions[].id` when present, else derived from the URL by a small site-side parser
  (EDI `packageid=` / `scope.identifier.revision`, NCEI `id=gov.noaa.nodc:…`, OBIS `/dataset/{uuid}`, IPT `r=`,
  Zenodo DOI, CalOOS `#module-metadata/{uuid}`) and dropped once the record carries it (§ D-9). Status is the
  semantic chip with its meaning in `title=`: *published* (ok), *planned* (warn, with the issue), *n/a* (quiet,
  with the reason where the record gives one), *external* (quiet), *superseded* (no-go, "replaced by …").

### D-7 · A holding page says where the data live today
