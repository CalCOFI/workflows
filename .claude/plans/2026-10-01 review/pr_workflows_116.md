## Iron-specific science: below-detection / censoring / contamination

- Source gives no detection limit and no non-detect code. The only non-value convention is the undocumented `-999`, which the notebook turns into NULL (correct: absent, not zero). Observed dissolved Fe range is 0.05-8.2 nmol/L with zero exact zeros and zero negatives (bounds table: n_zero=0, n_neg=0), so unlike ammonium (58% exact zeros) there is no zero-as-censored pattern to guard against here. BUT the minimum is a round 0.05, which is exactly what a detection-limit floor looks like; if several rows sit at 0.05 they may be "<LOD reported at LOD". The notebook neither counts rows at the minimum nor records this. Add a report line (n at min, n within 2x of min) and tie it to Q04; if provider confirms censoring, add a `measurement_qual` vocabulary entry (metadata/measurement_qual.csv) rather than publishing LOD-floor values as measurements. [Claude can add the report; qual vocab needs provider answer]
- Units are literally "nM/L" in the CSV header (nM per L, dimensionally nonsense) while the EML says nanomolePerLiter. The registry already publishes `nmol/L` before Q04 is answered. Reasonable reading, but it should be confirmed.
- Contamination: the abstract/methods describe trace-metal-clean GO-Flo / Teflon pump profiles, but the data contain only surface pole samples (Q03 resolved by inspection); pole sampling of surface Fe is the most contamination-prone mode. No blank, replicate, or contamination flag exists. Worth a provider question and a visible caveat in `dataset_meta` description/`quality_control_md` (currently "QC flags present: No.").
