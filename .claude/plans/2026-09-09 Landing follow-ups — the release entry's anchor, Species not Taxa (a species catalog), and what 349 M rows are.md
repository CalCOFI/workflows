So of the 349 M: **316.3 M are environmental measurements** (`obs_env` + the two full-resolution supplementals; 90.7 %),
**1.26 M are organism observations** (0.36 %), 26.3 M is the `obs` view counted twice (7.5 %), and 4.8 M is everything
else. Without the double count the release holds **322.4 M distinct rows**, 98.1 % of them measurements — the ratio of
measurements to organism observations is **251 : 1**. `calcofi4r::cc_get_db()` (1.22.0) attaches 20 tables: neither
supplemental table, so a reader who counts from R sees 57 M rows, not 349 M. `RELEASES.md` (v2026.09.04) already says
`obs` "is a view and will be dropped in the next release"; v2026.09.06 still shipped its parquet.

## Findings

- **F1** The release entry is the only link on calcofi.io that opens raw markdown; the anchored page it should open already
  exists, and each release has its own rendered `RELEASE_NOTES.html` beside it as well.
- **F2** The anchor id depends on a slug rule private to `render_md_on_storage.R` **and on the date in the heading**, so a
  consumer must reproduce both to link a version. Nothing links those ids yet, so the rule can change for free.
- **F3** "How and when a news entry is created" is answerable from four comments and a plan section; none of the docs or
  the README says it in one place, and the writing rule that matters most — the first `##` heading of a release section
  *is* the headline on calcofi.io — is nowhere.
- **F4** "2,614 taxa" is the size of the `taxon` table, not the number of organisms observed: **1,108 of the rows have no
  observation** (ancestors and unused vocabulary). The observed count is 1,506; at species rank, 1,008. The number was
  right by the letter of D-2 ("read, never typed") and wrong in what it says.
- **F5** The build can already compute the honest species numbers without a release: `coverage.json` (`taxa[]`, 1,506 rows
  with `rank`) is in every release since calcofi4db 3.25.0; `fetch_release.sh` simply does not pull it.
- **F6** "349 M rows" double-counts 26 M (`obs`) and is 78 % one supplemental CTD table; the organism observations, which
  are what a visitor imagines a "row" of CalCOFI to be, are 0.36 % of it. The two numbers a reader wants — measurements and
  organism observations — are both a sum over `tables[]` of the same `release_catalog.json` the build already fetches.
- **F7** A species catalog is the dataset catalog's pattern with the `taxon` table in the place of `dataset`: one record
  per key generated at release, one generator, one page per key with JSON-LD, one index with search, and every fact read.
  The record for it does not exist yet — `coverage.json` has counts per taxon × dataset but no lineage, and no per-year
  counts; `taxon.parquet` has the lineage but the Jekyll build reads no parquet.
- **F9** The record's ten biology dataset colours (`datasets[].color`) fail the categorical-palette check
  (dataviz validator, 2026-09-09): cufes yellow `#ffd43b` vs ichthyo orange `#ffa94d` ΔE 11 for normal vision
  (floor 15), zooscan pink `#f783ac` vs ZooDB teal `#38d9a9` ΔE 3.7 deutan; nine of ten are under 3:1 on white.
  They are fine as a *secondary* cue — which is how the site uses them — so the species catalog never lets a
  dataset dot stand alone: the name is always beside it, and the matrix is one sequential ramp.
- **F8** The Explorer's picker already folds by class and deep-links by `?taxon=`; a species page that opens the Explorer
  prefilled (Ben's rule: a tool opens prefilled from a link) needs nothing new on the Explorer's side.

## Decisions (each with a recommendation; the bold one is what the phases build)

### D1 — What the release entry links to, and how the anchor is made

(a) Keep `news.rb` mirroring the slug rule (`v2026-09-06-2026-09-06` from version + `release_date`). (b) **Make the
renderer stamp a stable id on every version heading — the version string itself, `id="v2026.09.06"` (dots are legal in an
id and a fragment) — keeping the slug ids on `##`/`###` headings and adding the slug id as a second, empty `<a id>` on the
version heading so nothing that might have bookmarked one breaks; `news.rb` links
`https://storage.calcofi.io/calcofi-db/ducklake/releases/RELEASES.html#v{version}`.** (c) Link each version's own
`{v}/RELEASE_NOTES.html` instead. *Recommend (b)*: Ben asked for the anchored heading in RELEASES.html; (b) makes the
anchor derivable from the one thing every consumer has (the version) and removes the date from the contract; (c) stays
as the *full notes* link on `/datasets/release/` where the generated appendix is the point. A range heading
(`# v2026.08.04 – v2026.08.06`, allowed by the skill) gets one id per version it names.

### D2 — Where "how and when a news entry is born" is written

**All four, each short**: (1) the landing README gains a section *News — where an entry comes from and when it appears*
with one table (type · source · who writes it · when it shows · where it links) replacing the dense paragraph; (2) the
docs book's `products.qmd` gains *§ The ship's log* (the same table, rendered from `news.yml` + `products.yml` +
`versions.json` at pre-render so the counts are real) and `releases.qmd` § The changelog gains two sentences — the
rendered page, the anchor, and that the first `##` heading becomes the headline on calcofi.io and in the feed — and links
`RELEASES.html` instead of the raw markdown; (3) the `release-run` skill § "RELEASES.md is not optional" gains the headline
rule; (4) `news.yml`'s header comment keeps the row format. *Recommend all four*: they are ~40 lines in total, and the
reader who needs each is a different person (a contributor, a data provider, the release runner).

### D3 — The word, and which count it labels

(a) "1,506 species" (observed taxa, the slightly-incorrect common word Ben allows). (b) **"1,008 species" on the band (the dt reads `species`; a band dt is one 12 px uppercase line in a
170 px tile, so the qualifier is the tile's tooltip), the Life tile reading "1,008 species — and 498 more taxa identified to genus, family or
class — every one keyed to WoRMS (ITIS for birds)"**, the tooltip on the band tile carrying the full breakdown. (c) keep
"taxa". *Recommend (b)*: it is the common word **and** exactly true, the qualifier is where a scientist looks for it, and
the species catalog's index says the rest. The `taxon` table's 2,614 stays where it belongs — the `/datasets/release/`
table of tables and the docs. Where the word appears elsewhere: the dataset page's `<dt>taxa</dt>` becomes "species" with
the same "of n taxa" qualifier only when the two differ; the catalog search hint and the docs keep *taxon* as the term of
art (the glossary gains a *species* entry that says exactly this).

### D4 — Where the species numbers come from, before the species record exists

**`fetch_release.sh` pulls `coverage.json` into `_data/release_coverage.json` (662 KB, build-time only, git-ignored, never
shipped to the browser — the same rule as `coverage_stations.json`); `datasets.rb` `numbers` gains `species`
(`taxa[].rank == "Species"`), `taxa` (its length) and keeps the table size as `taxon_rows`.** No release needed; the
number on the band changes the day it merges. When `taxa.json` (D7) lands, `numbers` reads the same two counts from it
and `release_coverage.json` is dropped again.

### D5 — What the species catalog is

(a) **A static catalog in the landing repo — `/species/` (index: search, the tree, the dataset matrix, the icicle) and
`/species/{taxon_key}/` (one page per taxon, JSON-LD `schema.org/Taxon`, sitemap, `search.json`) generated by a Jekyll
plugin from a release record, with the interactive parts in plain JS reading one inline JSON, exactly as `#reach` does;
every page opens the Explorer prefilled.** (b) A new Explorer lens. (c) A Shiny app. *Recommend (a)*: it is the dataset
catalog's proven pattern (`datasets.rb`, `check_jsonld.py`, `fetch_release.sh`, the layout probe), it is indexable — a
search for "Pacific sardine CalCOFI" should land on a page — it costs no server, and the Explorer keeps what it does best
(maps, sections, time series of one taxon) one click away rather than being duplicated. The Explorer's picker can later
fold by phylum/family from the same record (a bonus, not in scope).

### D6 — Which taxa get a page

(a) The 1,506 observed. (b) **Every `taxon` row with an observation at or below it — the 1,506 plus their 904 ancestors,
2,410 pages** — so *Sebastes* rolls up its 30 species and *Clupeiformes* rolls up sardine, anchovy and the herrings, and
the tree has no dead ends. (c) All 2,614. *Recommend (b)*: the 204 vocabulary-only rows have nothing to show and would be
2,614 − 2,410 pages saying "never observed"; they belong on the **dataset** page instead, as a folded list *"in the
vocabulary, not yet observed"* (a provider will want to know). A local key (`calcofi_phytoplankton:218`) is a page like any
other, headed by the dataset's own name for it and saying it is a dataset-local class. **The page is keyed by
`taxon_key` and nothing else** — one page per accepted id however many datasets carry it — at
`/species/{key with its ":" written "-"}/`: `/species/worms-217452/`, `/species/itis-176832/`,
`/species/calcofi_phytoplankton-218/` (the reverse split is on the last dash before the trailing digits, so a
dataset key's own hyphens survive). The JSON-LD `identifier` is the authority's LSID; the page title is the accepted
name once, never a dataset's.

### D7 — The record: `taxa.json`, written at release beside `datasets.json`

**`calcofi4db::build_taxa_catalog()` → `taxa.json` (schema `inst/schema/taxa.schema.json`, `schema_version` 1.0):**

```
{ schema_version, release{version, release_date},
  counts{taxa_observed, species_observed, taxon_rows, datasets, pages},
  datasets[]  {dataset_key, dataset_name_short, color, category{key,name,icon,realm}}   ← from the record, for the dots
  taxa[]      one per taxon row with an observation at or below it:
              {taxon_key, slug, worms_id, itis_id, gbif_id, ncbi_id, inat_id, scientific_name, common_name, rank, rank_order,
               taxonomic_status, status_checked, parent_taxon_key, lineage{kingdom, phylum, class, order, family},
               local{dataset_key, ds_scientific_name, ds_common_name, ds_taxa_code}   ← only for a dataset-local key
               groups[]  taxon_group_key,
               direct{n_obs, n_samples, n_datasets, year_min, year_max, life_stages[]},
               rollup{n_obs, n_taxa, n_species, n_datasets, year_min, year_max},        ← descendants included
               datasets[] {dataset_key, n_obs, n_samples, year_min, year_max, life_stages[], years{"1951": n, …},
                           sources[] {name, common_name, code, ids{worms_id, itis_id, gbif_id}, flags[]}}}   ← what this dataset calls it (one per dataset_taxon row)
  datasets[] (top level) also carry vocabulary_only[] {taxon_key, name, code} — the dataset's names with no observation anywhere (no page)
  flags[] ∈ synonym (the dataset's name is not the accepted name) · sp_to_genus ("Cyclothone sp." resolved to the genus)
           · rekeyed (the KEY authority's id the dataset supplied was deprecated and re-keyed to its successor; `taxon.notes`;
             27 Farallon rows) · id_conflict (a SECONDARY authority's id the dataset supplied disagrees with the key
             authority's cross-reference; 27 ichthyo rows whose ITIS hint differs from WoRMS's external link — refined
             2026-09-09 after the S1 agent found the two mixed) · no_name (the dataset carries only a code) — each computed
           by build_taxa_catalog(), each with a test
}
```

Written in `release_database.qmd` step **3b′**, after `datasets.json` (it reads the record's `datasets[]` for names and
colours) and before `eml/`; uploaded with the sidecars; added to `RELEASE_REQUIRED_OBJECTS`; a `test_release.qmd` gate
(`taxa_catalog`: schema valid, `counts.taxa_observed` == distinct `obs_bio.taxon_key`, every `parent_taxon_key` resolves,
every `datasets[].dataset_key` is in the record). Size: ~2,410 nodes × ~400 B + ~1,600 taxon × dataset rows with per-year
maps ≈ **2–3 MB**, build-time only; the browser gets the 270 KB tree the index inlines and a few KB per page. *Recommend
this over extending `coverage.json`*: `coverage.json` is the Explorer's first-paint payload and should stay lean; the two
files share `build_coverage()`'s taxon × dataset query, so the counts cannot disagree. Bridge exactly as Phase 0 did:
`TAXA_RELEASE_URL` (a full URL to a staging `taxa.json`) until a promoted release carries one, and the generator draws
no species pages at all when neither exists (D-2's rule: nothing typed).

### D8 — What the index shows (the interactive visualizations)

1. **Search + tree** (left column, ~40 %): a text box that matches scientific and common names and dataset names as you
   type; the tree folded to phylum by default, each node with its glyph-free count line — *n species · n observations ·
   dataset dots in the record's colours* — expanding down to species; a match expands and highlights its ancestors. Plain
   JS over the inline JSON; keyboard-navigable; `?q=` in the URL.
2. **The dataset matrix** ("which species in which datasets"): rows = the 23 classes (grouped by phylum), columns = the
   10 datasets in their catalog order, a cell = the number of taxa observed, sized as a square and tinted on one
   sequential ramp, with the count inside above a threshold; hover names the pair and lists the top three taxa; a click
   filters the tree to that class × dataset. It answers the question Ben asked in one figure.
3. **The icicle** (a horizontal partition of the hierarchy, Kingdom → Phylum → Class → Order → Family, sized by
   observations or by species — a toggle): the one "fancy" figure, click to zoom into a clade, a breadcrumb to climb out,
   the same dataset colours as dots on hover. It shows at a glance that Chordata is 64 % of the observations and 70 % of
   the species, that diatoms and dinoflagellates are one dataset, and that birds and mammals are their own world.
4. **The species page**: lineage breadcrumb (every ancestor a link), the names and ids (WoRMS · ITIS · GBIF, linked out),
   a row per dataset it is observed in — dataset · observations · samples · years · life stages — each row ending in
   **the name that dataset uses** with a quiet pill where it is not the accepted name (*synonym*, *sp. → genus*,
   *re-keyed*, *code only*; measured below) and a *status* pill in the header when the authority's own status is not
