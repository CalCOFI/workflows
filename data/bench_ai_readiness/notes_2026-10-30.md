**Changes made during the run (2026-10-30), recorded so the protocol is honest about them.**

1. **The raw-condition allowlist was widened, and every raw session was re-run.** The first Sonnet 5.5
   raw sessions were refused at hosts that serve the providers' own data:

   - `ccelter.ucsd.edu` (CCE-LTER ZooScan)
   - `library.ucsd.edu` (UC San Diego Library Digital Collections, which holds the SIO mesopelagic fish
     data)
   - `doi.org`
   - DataONE
   - CeNCOOS ERDDAP

   Those failures measured the sandbox, not the data. All raw sessions from before the fix were
   deleted and run again with the allowlist now in `run_agents.sh`.

2. **The bottle quality rule was made explicit in 10 questions** (R1, R4, I1, I4, I6, A1, A2, A3, A5,
   A6), and they were re-run for every configuration. The first wording said "unflagged". In the bottle
   database, quality codes 0–5 and 7 are undocumented, 6 means "OK, taken from CTD", and only 8
   (suspect) and 9 (missing) mark bad values. The reference (`qual_ok`) excludes only 8 and 9, but some
   sessions read "unflagged" as "no code at all". On I6 that gives 0.601 rather than 0.458 µmol/L,
   because the code-4 nitrate values are all 0. The questions now state the rule. The ambiguity is
   itself a finding for Aim 1: a bottle quality-code vocabulary in which most codes are undocumented
   costs an AI user (and a human one) a correct answer.

3. **U3 is scored as declared, which is strict.** U3 asks how many anchovy larvae were counted in CB
   bongo tows in 1972. The bongo net replaced the ring net in 1977–78, so no CB tows exist that year.
   Raw sessions that found this, said so, and still answered "0" are scored wrong, because the
   pre-declared rule for unanswerable items is to decline. The by-question table shows how many U3
   answers were "0" rather than NOT AVAILABLE.

4. **The raw sessions found a defect in the release, and the I1 and I2 references were corrected.**
   On I1, every raw session agreed on 14.47 °C, and on I2 most raw sessions said 1030, against the
   release's 14.36 °C and 1010. The raw agents were right. Release v2026.10.21 holds the July 2009
   cruise twice, with the same dates under two keys:

   - `2009-07-31M4` "MCARTHUR", derived from the bottle and picoplankton data.
   - `2009-07-33MH` "MCARTHUR II", the SWFSC reference used by ichthyo, CTD, ZooScan, PIC, seabirds
     and phytoplankton.

   No bottle cast from that cruise joins to anything else, and `check_cruise_key_integrity()` did
   not catch it. The reference SQL for I1 and I2 now maps the bottle key to the SWFSC key
   (commented in `questions.yml`), so it matches the providers' own cruise and station. Release
   sessions that trusted the release's key are scored against the corrected value:

   - I1 moves out of tolerance (14.36 vs 14.47, tolerance 0.1 °C).
   - I2 stays inside it (1010 vs 1030, tolerance 5%).

   This is the benchmark doing its job. A fix in the next release should raise the release
   condition's score on exactly these items, which is the per-release comparison Aim 2 proposes.

5. **R7 (dissolved iron) is behind a login at the provider.** No raw session answered R7. EDI
   refuses public reads of package `knb-lter-cce.21` ("Public Access is not authorized to execute
   service method 'listDataEntities'", checked with curl on 2026-10-30), and the CCE-LTER Datazoo
   copy needs a guest login with a name and email, which the agents correctly declined to invent.
   The release serves the same table openly. One host on that path, `gmn.lternet.edu`, was outside
   the raw allowlist, but it is a DataONE replica of the same restricted package.

6. **The forbidden-access audit counts URLs and paths only.** The first audit matched words anywhere
   in a tool call, so a Haiku session grepping a provider's web page for the word "zenodo" counted
   as a reach. It now matches only the URLs and paths a call uses, plus loading a CalCOFI client
   package (`bench_tool_forbidden()` in `score.R`, with inline checks).
   After the change, one call remains. A Haiku raw session on I6 (rep 3) found
   `calcofi.io/datasets/cce-lter_zooscan/` in web-search results and tried to `curl` its status
   code. The call was refused before it ran, and calcofi.io is outside the raw allowlist in any
   case. The session answered NOT AVAILABLE, so no release data reached a raw answer.
